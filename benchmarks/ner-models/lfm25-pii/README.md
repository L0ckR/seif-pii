# LiquidAI LFM2.5-Encoder-350M-PII-Detector

Отдельная ветка `experiment/lfm25-pii`, исходная точка — завершённый GLiNER
эксперимент `1fffea1`. Ветка GLiNER `experiment/gliner25-multi` сохранена,
`main` и опубликованный сервис остаются на spaCy. Здесь проверяется модель
локально; HTTP backend, Docker и production на LFM не переключались.

## Зафиксированный протокол

Модель: [`LiquidAI/LFM2.5-Encoder-350M-PII-Detector`](https://huggingface.co/LiquidAI/LFM2.5-Encoder-350M-PII-Detector/tree/b8c9cf3d2d6ae52501b35a27ba46f271449c9ce2),
revision `b8c9cf3d2d6ae52501b35a27ba46f271449c9ce2`, 354 648 993 параметра.
FP32, batch=1, seed=20260922, 4 CPU threads, RTX 4070 Ti SUPER, без обучения
и подбора порога. Первичная среда: обычный Python 3.13.7, Torch 2.14.0+cu130,
Transformers 5.11.0. Полные версии закреплены в
[`requirements-lfm.txt`](../../../deploy/ner/requirements-lfm.txt).

Сравниваются те же **5095** текстов: organizer 446, HiveTrace PII-Bench 1810,
Red Mad Robot 2839 после прежних двух исключений BIO-выравнивания. Данные,
порядок, разметка, baseline-кэши и исходники фиксируются до LFM inference.
Разметка organizer — прежний provisional AI silver, не официальный ground truth.
Публичные корпуса ранее использовались при разработке правил; GLiNER также
подбирался на organizer. Эта проверка не является полностью слепым тестом
всей системы, но по результатам LFM не меняются веса, пороги или правила.

Два декодера публикуются вместе, без выбора выигравшего после оценки:

- `raw`: неизменённый официальный BIOES argmax-декодер.
- `hybrid`: те же нейросетевые предсказания плюс официальные regex/валидаторы
  и context cues. Это часть решения автора модели, не обучение наших правил.

На каждый текст выполняется один нейросетевой проход. Для обоих декодеров
отдельно считаются PERSON-only, явно обозначенный address-proxy и native
маскирование всех 40 категорий. Веса, tokenizer и код автора не менялись.

## Различия задач

`identity.person_name` сопоставляется с PERSON в общей для трёх моделей задаче.
Обычной метки LOCATION у LFM нет. `contact.address` отображается в LOCATION
только в отдельном `gateway_address_proxy`; это практическая проверка
подключения, а не эквивалентность категорий. Правила СЕЙФ и merge одинаковы.

Официальный декодер не возвращает confidence. Значение **0.85** используется
только как заранее объявленный вес совместимости с merge (как у spaCy),
**не как вероятность модели**. Никакой порог confidence не подбирается.
Если адрес/имя превышает действующий лимит gateway 200 символов, соответствующий
профиль помечается недоступным на полном корпусе; такие случаи не отбрасываются
для получения более красивой метрики.

Native full masking измеряет объединение всех предсказанных буквенно-цифровых
позиций против всех gold-категорий. Пересечения считаются один раз; неизвестные
или неподдерживаемые категории не скрываются. Этот режим не включает правила
и фильтры СЕЙФ, поэтому имеет другую задачу, чем NER-вставка в наш сервис.
`identity.ssn` не объявляется СНИЛС, national ID — паспортом РФ, а tax ID —
валидированным российским ИНН.

## Проверки загрузки и границ

Официальный helper ограничивает вход 2048 токенами. Проверены все 5095 входов:
максимум **416** на organizer и **1111** на публичных корпусах, превышений нет.
[`token-length-preflight.json`](token-length-preflight.json). Wrapper дополнительно
отклоняет слишком длинный ввод и сверяет фактическое число токенов после helper,
поэтому молчаливое обрезание не принимается.

Источником категорий служит `model.config.id2label`: **161 BIOES-метка, 40 типов**.
Файл `label_schema.json` в snapshot содержит устаревшие 109 меток и не используется
для декодирования. До исполнения проверяются SHA-256 весов, config, tokenizer и
трёх Python-файлов автора; обязательные context helpers загружаются явно.
Вспомогательный `context_cued.hybrid_with_context()` с абсолютным путём автора
не вызывается. Custom code меняет классы LFM2 внутри Transformers, поэтому
эксперимент использует отдельные среду и процесс от GLiNER.

[`wrapper-smoke.json`](wrapper-smoke.json): реальный CUDA wrapper дал точно
те же spans, что и неизменённые официальные helpers, на трёх синтетических
примерах, включая пустой ввод и Unicode/emoji. Это проверка нативного inference,
не HTTP или заявленная производительность сервиса.
