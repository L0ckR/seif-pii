# RuBERT PII: TensorRT FP16 + CUDA Graphs

Эксперимент `experiment/rubert-tensorrt` от `2213f27` проверяет
[`lockR/rubert-base-pii-ner-tensorrt`](https://huggingface.co/lockR/rubert-base-pii-ner-tensorrt/tree/73be581047bf123dac6505e7b3900ec292942296),
revision `73be581047bf123dac6505e7b3900ec292942296`.
Базовая модель — `redmadrobot-rnd/rubert-base-pii-ner`, экспорт без дообучения.
Ветка содержит экспериментальный адаптер и измерения; основной сервис не переключён.

## Качество

Все **5095/5095** текстов обработаны без ошибок. Порог 0.3, batch=1,
опубликованные окна 512 токенов с перекрытием 128, без подбора по результатам.
Те же тексты, разметка и правила, что в экспериментах GLiNER/LFM/ONNX.
Предыдущие агрегаты spaCy и GLiNER воспроизвелись точно до запуска модели.

Главная метрика — F1 фактического маскирования буквенно-цифровых позиций;
учитываются **все** исходные gold-типы, включая неподдерживаемые.
В таблице одинаковый профиль сервиса: правила + PERSON/LOCATION из модели.

| Корпус | Текстов | spaCy + правила | GLiNER + правила | RuBERT + правила | Изменение к GLiNER, п.п. |
|---|---:|---:|---:|---:|---:|
| Organizer | 446 | 96.8856% | 97.4598% | **96.8791%** | −0.5807 |
| PII Bench | 1810 | 71.9545% | 71.7599% | **74.0731%** | +2.3132 |
| Red Mad Robot | 2839 | 59.4971% | 65.6560% | **69.7101%** | +4.0541 |

Полностью правильные маски RuBERT: **412/446**, **1194/1810**, **1219/2839**.
У GLiNER соответственно 423, 1143, 1094. Organizer precision/recall RuBERT:
97.0233% / 96.7353%; GLiNER: 97.7782% / 97.1434%.
На 329 уверенно размеченных organizer-текстах RuBERT даёт F1 **99.1096%**,
320 точных масок; GLiNER — 99.4859%, 328 точных масок. У RuBERT здесь
72 лишних и 1 пропущенный буквенно-цифровой символ. Автоматическая замена
по этому эксперименту не оправдана: перенос на внешние корпуса лучше,
но organizer ухудшился, включая уверенную часть разметки.

`FIRST_NAME/LAST_NAME/MIDDLE_NAME` отображаются в PERSON,
`CITY/COUNTRY/DISTRICT/REGION/STREET/HOUSE` — в LOCATION. Заранее зафиксировано
объединение соседних одинаковых укрупнённых типов через пустой промежуток/пробелы;
confidence берётся максимальная из компонентов, пунктуация не расширяется.
Это более широкий адресный охват, чем географические названия GLiNER.
Предсказания native21 сохраняют исходные типы и границы независимо от mapping.

typed-character F1 — **91.5751%**. Exact-span F1 IP_ADDRESS только 36.0215%,
INN — 67.9537%, SNILS — 77.9097%: контекстные правила и валидаторы остаются полезны.

Полные метрики, включая PERSON-only и точные типизированные границы:
[`comparison.json`](comparison.json).

Разбор [`error-analysis.json`](error-analysis.json) выявил всего 12 изменившихся
итоговых масок относительно GLiNER:11 теряют точное совпадение, ни одна его

в исходных предсказаниях, coarse объединение не добавило ни одной буквы/цифры.
17 символов в 4 случаях — фрагменты обычных слов; 15 — ссылки на офисы,
отнесённые к HOUSE/LOCATION. Для последующих изменений полезны общие проверки
границ слова и контекста адреса; настройки по этим примерам здесь не менялись.
Из 22 новых FN 20 относятся к одному неуверенно размеченному случаю, где GLiNER
пометил номер документа как PERSON: untyped-mask метрика засчитала защиту,
хотя тип был ошибочен. Оставшиеся 2 — окончание имени и пропущенный инициал.

## Скорость модели

RTX 4070 Ti SUPER, Python 3.12.11, TensorRT 10.13.3.9, Torch 2.8.0+cu128,
Transformers 4.57.1. Движок соответствует GPU и версиям сборки, пересборки нет.
FP16 с FP32 accumulation для normalization, TF32 отключён.
Все пять CUDA Graph buckets прогреты до измерения. Графы повторяют вычисления,
а не возвращают кэшированные предсказания.

| Корпус | Текстов/с | p50, мс | p95, мс | p99, мс |
|---|---:|---:|---:|---:|
| Organizer | **895.79** | 0.974 | 1.811 | 2.502 |
| PII Bench | **880.53** | 1.001 | 1.823 | 2.244 |
| Red Mad Robot | **715.89** | 1.116 | 2.558 | 6.215 |

Вызов включает tokenizer, все overflow windows, передачи CPU/GPU, синхронизацию,
decoder, валидацию и coarse mapping. Сериализация кэша и загрузка исключены.
Это последовательные **тексты/с, не HTTP RPS**; короткий однопроходный замер
на общей рабочей машине, без гарантии её полной изоляции. Предыдущий GLiNER ONNX
на organizer давал 43.78 текста/с: наблюдаемая разница около 20.5×, с разными
моделями и отдельными запусками, а не ускорение одной и той же модели.

Каждая фаза содержит все 446 уникальных organizer-текстов, каждый запрос
имеет новый payload ID. API — один worker Python 3.14.7t без GIL;
NER — один worker Python 3.12.11 с одной последовательной очередью модели.

Два дополнительных прогона с 8 клиентами многократно отправляют весь корпус

| [50 циклов](http-trt-graph-repeat50.json) | 22300 | 41.49 с | **537.51** | 19.70 | 22.50 | 54.02 |

В обоих прогонах 100% HTTP 200 и reference parity, число завершённых NER-вызовов
равно числу mask-запросов, ошибок 0; restore/failclosed тоже прошли.
На 50 циклах измерено 22300 фактических вызовов модели, а не replay масок.
Более короткий C8 прогон 298 RPS также сохранён. Во всех трёх запусках одинаковые
driver Python 3.14t, API/NER interpreters, настройки и зависимости.
Разница не объясняется постепенным прогревом в repeat20: уже первый цикл
имеет p50≈14.79 мс, последний≈15.86 мс. Конкретная причина разброса между
отдельными запусками не измерена. Корректный вывод: около 538 RPS воспроизведено
на повторном корпусе в двух проверках, одна до 41.5 с; предел устойчивой
пропускной способности и длительный SLA этим не установлены.

Во всех 1784 запросах короткой серии: HTTP 200, реальные завершённые NER-вызовы,
совпадение масок, границ и типов с собственным RuBERT-кэшем; ошибок нет.
8/8 выборочных восстановлений в каждой фазе точны. После остановки NER
новый mask и health возвращают 503. Ни одного ответа дольше 500 мс.
Совпадение с кэшем подтверждает HTTP-корректность, а не идеальное качество gold.

Прежний GLiNER ONNX давал 49.86 RPS при 4 клиентах. В той же конфигурации
RuBERT даёт 271.59, наблюдаемый прирост примерно 5.45×; это отдельные запуски
на одной машине, а не одновременный парный тест. При 16 клиентах скорость
не растёт, задержка увеличивается. Тест закрытого цикла, без Redis, capture,
batching и репликации; он не доказывает 2000 RPS либо SLA production.

### Устранённое искажение первоначального HTTP-замера

[`http-trt-graph.json`](http-trt-graph.json) сохранён: все проверки корректности
успешны, но throughput ограничился 83 RPS. В первой NER-среде не было
`uvloop`/`httptools`, и тестовый запуск Uvicorn с унаследованным `--fd`
использовал asyncio/h11. Измеренная задержка ответа на повторно используемом
private NER TCP-соединении была около 48 мс: около 4 мс до заголовков,
ещё 43 мс до тела, при серверном обработчике около 3 мс и модели около 2 мс.
На новом соединении весь запрос занимал около 4.8 мс.

Просмотр кода выявил условие для Nagle/delayed ACK: Uvicorn оборачивает
полученный fd как AF_UNIX, а asyncio включает TCP_NODELAY только для
INET/INET6 TCP-сокетов. Это объяснение по коду и timings, не packet capture.
Добавление **uvloop 0.22.1 и httptools 0.8.0**, как в прежнем GLiNER-окружении,
устранило задержку без изменения модели, порога, сервиса или benchmark-клиента.
Исходная зависимость окружения сохранена в [`environment-initial.txt`](environment-initial.txt).
Разбор actual NER timings — [`transport-diagnostic-initial.json`](transport-diagnostic-initial.json),
выровненное окружение — [`environment-http-aligned.json`](environment-http-aligned.json).
Независимая проверка без модели — [`transport-diagnostic.json`](transport-diagnostic.json):
asyncio даёт около 43 мс ожидания тела и с h11, и с httptools; uvloop — около 0.01 мс
с обоими парсерами. Во всех четырёх вариантах фактически измерены
`family=AF_UNIX`, `proto=0`, `TCP_NODELAY=0`. Следовательно, uvloop устранил
наблюдаемую задержку без включения TCP_NODELAY; вероятное объединение записей
здесь не исследовано. Утверждения, что исправление включило NODELAY, нет.
Диагностика воспроизводится отдельным `transport_diagnostic.py` без GPU.

## Воспроизводимость

[`provenance.json`](provenance.json) содержит SHA256 15 файлов. Их локальные
копии сверены с Git blob/LFS hashes опубликованной pinned-ревизии через HF API.
Перед исполнением проверены исходники runtime; загрузка tokenizer локальная,
во время эксперимента сеть запрещена. Веса, тексты и кэши находятся в ignored
`local-data/`, в Git сохранены код, протокол и отчёты без исходных текстов.

[`protocol.json`](protocol.json) фиксирует настройки, исходники, зависимости,
порядок, тексты, gold и baseline-кэши до inference. Любая ошибка в отдельном
тексте делает качество всего его корпуса недоступным, а не исключает строку.
Адаптер дополнительно проверяет logits `[batch, padded_tokens, 43]`, конечность
значений, Unicode offsets, соответствие текста и ограничения gateway.

Синтетический smoke проверяет пустой ввод, `!`, отсутствие маскирования слова
«клиент», ФИО с документами и имя в конце текста длиной 12027 символов:
[`synthetic-smoke.json`](synthetic-smoke.json). Все проверки прошли,
все buckets 32/64/128/256/512 захвачены, длинный ввод не обрезан.

Для повторения нужен Python 3.12 и совместимая NVIDIA GPU. Движок привязан
к окружению; на другой GPU/TRT требуется пересборка и новый эксперимент.

```bash
uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python \
  --extra-index-url https://download.pytorch.org/whl/cu128 \
  -r deploy/ner/requirements-rubert-tensorrt.txt
.venv/bin/hf download lockR/rubert-base-pii-ner-tensorrt \
  --revision 73be581047bf123dac6505e7b3900ec292942296 \
  --local-dir local-data/rubert-tensorrt/model
# PUBLIC_DIR — прежний frozen gliner25-public run с 4649 public inputs/caches.
# Каждое новое измерение требует пустого RUN_DIR внутри local-data/.
.venv/bin/python scripts/compare_rubert.py prepare \
  --run-dir "$RUN_DIR" --public-run-dir "$PUBLIC_DIR" \
  --model-path local-data/rubert-tensorrt/model
.venv/bin/python scripts/compare_rubert.py cache \
  --run-dir "$RUN_DIR" --public-run-dir "$PUBLIC_DIR" \
  --model-path local-data/rubert-tensorrt/model
.venv/bin/python scripts/compare_rubert.py evaluate \
  --run-dir "$RUN_DIR" --public-run-dir "$PUBLIC_DIR" \
  --model-path local-data/rubert-tensorrt/model --output "$RUN_DIR/comparison.json"
# API_PYTHON — Python 3.14t с зависимостями самого сервиса; используется и как driver.
"$API_PYTHON" benchmarks/ner-models/rubert-tensorrt/http_benchmark.py \
  --api-python "$API_PYTHON" --ner-python .venv/bin/python \
  --model-path local-data/rubert-tensorrt/model \
  --reference-cache "$RUN_DIR/rubert-organizer.jsonl" \
  --concurrency 8 --repeats 50 --output "$RUN_DIR/http-repeat50.json"
```

Organizer 446 имеет предварительную AI-разметку, а не официальный ground truth.
Публичные корпуса уже использовались для правил. RuBERT обучен на `pii_train`
того же источника Red Mad Robot; совпадения с обучающим набором здесь не проверены.
Наш frozen RMR сохраняет прежние 2839 строк и два исключения выравнивания;
карточка модели использует 2841 строку с иной обработкой двух строк. Поэтому
карточка и этот отчёт не обязаны совпадать. Ни одна приведённая F1 не является
общим баллом хакатона или его закрытой метрикой Levenshtein.
