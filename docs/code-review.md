# Исправления после локального ревью

Полученный внешний отчёт содержит только агрегированные счётчики замечаний,
без правил, файлов и строк. Ни одно исправление ниже не объявляется устранением
конкретного замечания внешнего анализатора; его новый балл требует повторной
загрузки ZIP в систему организаторов.

Проверялись API, конфигурация, хранилище, NER, преобразование текста, запись
запросов и инструменты сборки/измерений. Данные организаторов не использовались
для подбора правил распознавания.

| Подтверждённая проблема | Исправление и проверка |
|---|---|
| Строковое `"false"` в флагах доступа интерпретировалось как истина | Строгие boolean для политик и demo; регрессии на YAML и программной конфигурации |
| Некорректные числовые лимиты могли отключать ограничения | Положительные целочисленные лимиты и конечный положительный срок загрузки проверяются при создании конфигурации |
| Незавершённый POST удерживал слот и память без срока | Общий срок загрузки тела: API 30 с с настройкой через окружение, NER 5 с; ответ 408, ресурсы освобождаются, время обработки после загрузки не затрагивается |
| Анонимное исключение `/health` в NER распространялось на POST | Анонимный health доступен только через GET; тест отклоняет POST до чтения тела |
| Повторение известного токена позволяло резко увеличить ответ | Предварительный расчёт итогового размера и 413 до подстановки; корректное последующее восстановление той же записи сохраняется |
| Пользовательский тип с цифрами создавал невосстанавливаемый токен | Грамматика разбора соответствует разрешённым именам типов; проверены редактированные ответы с повторением токена |
| Пустое или слишком длинное совпадение пользовательского правила молча игнорировалось | Отказ обработки для совпадений вне 1–4096 символов, вместо пропуска защиты |
| Точное восстановление многократно копировало весь документ | Один проход по заменам, проверка координат и сохранённых значений; регрессия на 5000 замен с Unicode |
| Равные кандидаты зависели от случайного порядка множества между процессами | Детерминированное разрешение равенства; проверка разных `PYTHONHASHSEED` |
| Некорректные политики могли оставить созданные до валидации ресурсы | Полная проверка политик предшествует созданию клиентов и пула |
| Вложенный JSON health мог выходить за ожидаемую обработку ошибок NER | Безопасная нормализация ошибки; общий NER-токен исключён из `repr` настроек |
| Сборщик ZIP мог читать файлы по симлинкам и повреждать прежний ZIP при сбое | Обход только разрешённых каталогов/форматов, исключение симлинков и атомарная замена после успешной сборки; импорт модуля больше не запускает сборку |
| Неконечные параметры нагрузки могли создавать бесконечный прогон | Проверки NaN/Inf и верхних границ до открытия соединений |
| HTTP-перенаправление могло увести тестовую нагрузку и нестандартные заголовки ключей на другой адрес | Перенаправления генератора запрещены; локальная проверка с двумя HTTP-серверами |

В постоянный Ruff-набор включён Bugbear. Для сопоставляемых последовательностей
добавлен `zip(strict=True)`; скользящие пары явно используют `strict=False`.
Правила внешнего анализатора не отключались и замечания не подавлялись ради счёта.

Проверки конфигурации, таймаутов, восстановления, ZIP и нагрузки находятся в
`tests/test_api_hardening.py`, `tests/test_ner_service.py`,
`tests/test_transform_review.py`, `tests/test_package.py` и
`tests/test_synthetic_benchmark.py`. Окончательная сводка находится в `code-review-validation.json`.

Результат локального ревью не подтверждает качество распознавания 95%, отсутствие
всех дефектов или успешное прохождение закрытой проверки организаторов.


## Окончательная проверка

- **886 тестов прошли, 0 пропусков**, CPython 3.14.7t без GIL; включены настоящий Redis и переключение Sentinel после отказа primary. Ruff и `git diff --check` прошли.
- Через настоящий приватный NER проверены все 3 демо во всех 3 режимах: точное восстановление, метка «Клиент:» видима, ФИО защищено.
- После исправлений: **1000 заданных RPS в течение 60 секунд**, фактически 999,867; 60 000 успешных HTTP-запросов, 30 000 точно восстановленных пар, без пропусков/ошибок; p95 15,969 мс, p99 21,971 мс, максимум 87,598 мс. Запись включена, все 60 000 запросов записаны без потерь.

Нагрузочная проверка использует отдельный loopback-стенд с 3 API-workers, 8 NER-workers, 3 Redis и 3 Sentinel; смесь маскирования/восстановления 50/50 на 446 ранее разрешённых текстах длиной до 995 символов. Это проверка регрессии за 60 секунд, не повторное пятиминутное подтверждение предела и не замер через Cloudflare. Исходники корпуса и экспериментальные записи остаются под `.gitignore`. Первый прогрев имел некорректный начальный счётчик записи после демо; он сохранён отдельно, после синхронизации счётчиков оба этапа повторены.
