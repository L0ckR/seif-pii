# Внешние данные для проверки русских ПД и языков СНГ

Выполнены три внешних первых прогона: **HiveTrace PII-Bench, 1 810 строк**; **Red Mad Robot, 2 839 из 2 841 строки после заранее объявленной проверки BIO-выравнивания**; **Scanpatch, все 532 смешанных RU/UK-документа**. На первом сопоставимом срезе СЕЙФ выиграл; на втором выбранная русская конфигурация Presidio оказалась лучше. Финальный PERSON+LOCATION-гибрид расширил покрытие, но его превосходство над baseline на третьем наборе не подтверждено. Все первые отчёты сохраняются. Отсутствие языка каждой строки Scanpatch не позволяет объявить отдельный RU/UK benchmark.

Источники и версии проверены 22 сентября 2026 года. Ниже указана лицензия, объявленная самим издателем, и отдельная ссылка на файл нужного split. Модельные веса и полные многоязычные обучающие корпуса для этого исследования не скачивались.

Для оценки по языкам сначала нужна независимая разметка языка, выполненная без результатов детектора, либо следует публиковать только результат смешанного набора.

## Почему основной тест — HiveTrace

Издатель сообщает, что тексты сгенерированы, затем проверены и независимо размечены двумя носителями русского языка. Имена и ADDRESS полезно оценивать отдельно от форматных идентификаторов; ADDRESS размечен целиком, а не как набор города/улицы/дома. В `domain` есть 100 примеров банковской поддержки. Это внешний авторский benchmark, но синтетический, а не случайная выборка банковского трафика. [Описание построения и evaluation notes](https://huggingface.co/datasets/hivetrace/pii-bench#construction-and-annotation).

В [закреплённой карточке](https://huggingface.co/datasets/hivetrace/pii-bench/blob/cd6a18ace16daf23e79247ccf1e2b245d4054654/README.md) раздел License прямо указывает Apache-2.0. Просьба не обучаться на benchmark сформулирована отдельно от лицензионных ограничений. В README связанного [GitHub-проекта](https://github.com/HiveTrace/gliner-guard) описание условий benchmark отличается. В этой работе набор используется только для оценки; его тексты не добавляются в training, тесты регрессий или исходный ZIP. В отчёт сохраняются источник, версия и это расхождение, а не обобщение лицензии кода на все артефакты.

## Первый внешний прогон: что уже измерено

[`pii-bench-comparison.json`](pii-bench-comparison.json) содержит первый слепой результат замороженного детектора `d3a66e2de0a42beb34c411504e1187d0ae1b0f280291084d040a10269480980b`. SHA-256 входного `domain` — `7ef3574273c0fe3a987981e38e32cd2764031a82766ca5b235bfccd1f27058eb`; `entity` — `6e0c77d566c2f04e7213917b26f1038336e28fc006551fac7a7f44f7627d5f96`. Проверены все исходные Unicode-spans; ошибок соответствия подстроке не найдено, метки не исправлялись. Исходные тексты не включаются в репозиторий или ZIP.

| Срез / exact-span F1 | СЕЙФ, правила | Presidio RU | СЕЙФ hybrid |
|---|---:|---:|---:|
| `domain/common4`: 612 примеров, 315 сущностей, 378 отрицательных | **99,20%** | 96,26% | 97,36% |
| `entity/common4`: 280 примеров, отрицательных нет | 98,37% | 98,07% | 98,07% |
| `domain/supported8`: 787 примеров; диагностическое покрытие типов ТЗ | 85,77% | 74,59% | 84,06% |

На основном срезе `domain/common4` 95%-интервалы парной разницы F1 с Presidio положительны: правила +1,28…+4,80 п.п., hybrid +0,17…+2,29 п.п. На `entity` интервал правил включает ноль: −1,17…+1,72 п.п. Bootstrap использует 2 000 повторов, стратификацию по домену и фиксированный seed; корреляции синтетических шаблонов не учтены. Это доказательство для данного протокола и набора, не универсальное превосходство фреймворка и не 95% покрытия банковских ПД.

Адреса остаются слабым местом: при приведении компонентов к ADDRESS recall символов правил **52,30%**, F1 **64,81%**; у LOCATION-proxy Presidio F1 **46,63%**. Raw exact-span F1 — 8,14% против 10,23%. Отличие границ полного адреса от компонентов объясняет часть потери, но не отменяет реальных пропусков. Подробный баланс NAME/ADDRESS, precision/recall и описание baseline находятся в [сравнении Presidio](presidio.md).

После публикации этих чисел разработана самостоятельная адресная грамматика без чтения её разработчиком внешних примеров. Направление изменения уже выбрано по результату, поэтому повтор HiveTrace считается **диагностикой после разработки**, а не новым blind-результатом. Для независимого подтверждения использован Red Mad Robot, описанный ниже. Региональные проверки семи соседних стран находятся в [cis.md](cis.md); эти русские корпуса не проверяют все местные языки.

## Второй внешний прогон: Red Mad Robot

Зафиксированы revision `f77ea831274daf980cc45c61a93c226be9d978d6`, SHA-256 `test.csv` **`6bf544a380a3ee5bec94b946124bea3afaecce49e734679ad0f0c0e7c12977bb`**, оригинальный русский test и MIT из карточки издателя. Исходный текст не пересобирается из токенов. Буквальное последовательное выравнивание исключило до inference две строки: `row_0000`, `row_1628`. Пустой токен O обозначает ноль символов и сохраняет границу BIO. Все системы получили остальные **2 839** строк.

Протокол SHA-256 **`30c44a48cd151dc72b61d804a979ddd0e3203fd78ac79dbac2d5d8e7f50e86b1`** закреплён до запуска. Детектор: `c45e8f6106ea0f7c3c1cf8358c93a7ce2592a1f9b28a226afaa0ac9868ce4c31`. FIRST/LAST/MIDDLE_NAME приводятся к PERSON, шесть пространственных компонентов — к LOCATION. Одинаковое объединение пересекающихся или разделённых только пробелами spans применяется к gold и всем системам; запятые и границы не исправляются по результатам.

Основной срез — **1 237 целых примеров, 371 отрицательный**, только PERSON/LOCATION/EMAIL/PHONE/CARD. Главное число — micro-F1 **символов с правильным типом**; exact-span F1 после общего merge — дополнительная метрика.

| Система | Precision символов | Recall символов | F1 символов | Merged exact-span F1 |
|---|---:|---:|---:|---:|
| СЕЙФ, правила | 94,72% | 30,61% | 46,27% | 30,95% |
| Presidio RU | 83,75% | 49,65% | **62,34%** | **53,91%** |
| СЕЙФ, PERSON-hybrid | 84,38% | 38,01% | 52,41% | 37,70% |

95%-интервал парной разницы главного F1 с Presidio: правила **−19,77…−12,42 п.п.**, PERSON-hybrid **−13,05…−6,90 п.п.** Bootstrap использует одну группу выбранных строк, неизвестные домены не придумываются. На всех 2 839 строках PERSON F1 символов: 45,80% / 63,01% / **67,46%**; LOCATION: 32,02% / **65,67%** / 32,02%. Объединение имён помогает, но пространственный канал существенно уступает baseline.

Пересечение с PDF ограничено: **13 исходных меток** имеют прямое соответствие — три части ФИО, COUNTRY/CITY/STREET/HOUSE, EMAIL/PHONE, PASSPORT/INN/CREDIT_CARD/DRIVER_LICENSE. REGION/DISTRICT — ещё **два компонента адреса**, сопоставляемые только в общей пространственной категории. URL/IP_ADDRESS/SNILS/OMS/MILITARY_ID/BIRTH_CERTIFICATE — **шесть меток без однозначного соответствия** схеме ТЗ. Корпус не проверяет отдельно орган/дату выдачи и код подразделения, назначение даты рождения, гражданство, CVV/PIN и поле владельца карты. LOCATION не означает автоматически полный личный ADDRESS; публичные/частные gold-метки не менялись под нашу политику.

Первый отчёт — [`redmadrobot-comparison.json`](redmadrobot-comparison.json), оценщик — [`evaluate_redmadrobot.py`](../scripts/evaluate_redmadrobot.py): `--prepare-only` фиксирует протокол, отдельный запуск выполняет inference, `--repeat` явно помечает повтор. Leaderboard издателя использует overlap matching и подобранные пороги, поэтому его числа не сравниваются с нашими. Данные и исходные предложения остаются в игнорируемом `output/`; в репозиторий и ZIP входят код, протокол и агрегаты.

Здесь универсальное превосходство над Presidio **не подтверждено**. Добавление LOCATION было development-изменением. Отдельная абляция по сохранённым PERSON/LOCATION-предсказаниям улучшила F1 символов гибрида до **68,44%** (exact 54,76%), но это не независимый результат: корпус уже повлиял на архитектуру. Исходный отчёт сохранён; абляция записана отдельно в [`redmadrobot-location-ablation.json`](redmadrobot-location-ablation.json).

## Финальный holdout: Scanpatch, только смешанный RU/UK результат

Использован весь исходный `test` — **532 строки**, revision `6af0587dde068d90d8a1080285159c374b46a09b`, MIT. Train из 4 786 строк не скачивался. SHA-256 Parquet: **`5d44f419692282285ae811bd54b69e57bb44121e31f3628408e203f9416371ba`**. Все spans совпали с исходными подстроками; исключений и исправлений нет. Зафиксированы protocol **`2152d14d65a3c3076e3f4c8e8e8001e07216e89b628dfbe574478e81207eb4b1`** и детектор **`732dabbdfbec9b37727e247481958a7dbc157cc1cb53409231bf9398100c1508`**.

В данных есть вложенные полные имена/их части и адреса/компоненты. Одинаковое coarse-приведение и объединение пересечений либо пробельных промежутков применяется к gold и всем предсказаниям; никакой агрегации по результатам системы нет. Общий срез состоит из **164 целых строк, включая все 58 отрицательных**. CARD отсутствует во всём test: common5-схема здесь положительно проверяет только PERSON/LOCATION/EMAIL/PHONE.

| Детектор | Precision символов | Recall символов | F1 символов — основной | Merged exact-span F1 |
|---|---:|---:|---:|---:|
| СЕЙФ, правила | 84,04% | 35,25% | 49,67% | 38,88% |
| Presidio RU | 82,95% | 64,44% | **72,53%** | **62,32%** |
| СЕЙФ, PERSON+LOCATION hybrid | 78,25% | 61,67% | 68,98% | 57,99% |

95%-интервал разницы основного F1 hybrid−Presidio **−8,35…+0,41 п.п.** включает ноль: доказанного преимущества нет. Для дополнительного exact-span показателя интервал **−7,64…−1,21 п.п.** отрицателен. Bootstrap использует 2 000 парных повторов и одну группу всех выбранных строк; несуществующие языковые/доменные gold-группы не придумываются.

С PDF прямо пересекаются пять вариантов имён, mobile_phone/email, tin и семь адресных категорий: полный address, country, city, street, house, apartment, postal_code. region/district/building — только компоненты общего LOCATION; geolocation явно не требовался заданием. document_number не различает паспорт, права или иной документ. Корпус не даёт отдельной проверки CARD/CVV/PIN, органа и даты выдачи, кода подразделения, гражданства и назначения даты рождения. Полный перечень и количества находятся в отчёте.

Источник называет тексты синтетическими, разметку — LLM-аннотацией по проверенным правилам. Надёжного поля языка нет; **русская ru_core_news_sm применена ко всему mixed-набору**, и это не лучшая возможная украинская настройка Presidio. Результат не доказывает покрытие всех языков СНГ, всех банковских ПД или соблюдение публичных исключений ТЗ.

Первый неизменяемый отчёт — [`scanpatch-comparison.json`](scanpatch-comparison.json), оценщик — [`evaluate_scanpatch.py`](../scripts/evaluate_scanpatch.py). После этой оценки модели, пороги и правила не менялись по её результатам. Дальнейшая разработка требует нового непросмотренного теста; тексты текущих корпусов не входят в Git или исходный ZIP.

## Что проверено, но не выбрано для основного прогона

**NEREL** полезен для вложенных PERSON/CITY/COUNTRY/DATE и связей вроде даты/места рождения. У него нет готовой полной схемы банковских документов. Доступны BRAT `.txt/.ann` в `NEREL-v1.1/test`, например [текст](https://raw.githubusercontent.com/nerel-ds/NEREL/8f07d3e410f322d5dbf6b68b13fbf4a4aa077fe9/NEREL-v1.1/test/1130.txt) и [аннотация](https://raw.githubusercontent.com/nerel-ds/NEREL/8f07d3e410f322d5dbf6b68b13fbf4a4aa077fe9/NEREL-v1.1/test/1130.ann). В [авторской статье](https://aclanthology.org/2021.ranlp-1.100/) указан CC BY 2.5 для исходных новостей Wikinews; отдельной лицензии аннотаций в проверенном [репозитории](https://github.com/nerel-ds/NEREL) не обнаружено. Нельзя автоматически объявлять весь набор MIT или CC BY-SA по лицензии сторонней конверсии.

**WikiANN** содержит ru/uk/kk и готовые splits, но является общим NER на Wikipedia, а не PII-разметкой. В [карточке University of Melbourne](https://huggingface.co/datasets/unimelb-nlp/wikiann) лицензия указана как `unknown`; его не выбираем вместо набора с ясным опубликованным условием и более подходящей задачей.

**BSNLP 2019** содержит русский, болгарский, чешский и польский; украинского в этой редакции нет. Задание не требовало offsets каждого упоминания, поэтому это не готовый drop-in exact-span тест. Test доступен со [страницы организаторов](https://bsnlp.cs.helsinki.fi/bsnlp-2019/shared_task.html), но явные условия лицензии там не найдены. Он полезен для русской морфологии и вариантов имени, не для проверки паспорта/ИНН.

**AI4Privacy 65k/200k** в проверенных карточках перечисляют en/fr/de/it, а **300k** — дополнительно es/nl. Они не являются русским набором только из-за популярности в PII-оценке. Новые поколения семейства нужно исследовать отдельно, а не переносить на них язык или лицензию старого выпуска. [65k](https://huggingface.co/datasets/ai4privacy/pii-masking-65k), [200k](https://huggingface.co/datasets/ai4privacy/pii-masking-200k), [300k](https://huggingface.co/datasets/ai4privacy/pii-masking-300k).

**`wolframko/russian-pii-66k`** тематически близок российским ПД, но в проверенной карточке нет явной лицензии, опубликован только train. Поэтому его не используем как готовый независимый test. [Карточка издателя](https://huggingface.co/datasets/wolframko/russian-pii-66k).

## Протокол внешнего измерения

Эти принципы применены к первому прогону и сохраняются для следующего holdout.

1. **Заморозить вход до inference.** Зафиксировать revision, URL, SHA-256 файла, список всех 900 ID, хеши кода детекторов и конфигурацию модели. Проверить уникальность ID и равенство `text[start:end]` размеченному значению. Ошибки разметки перечислить отдельно; не исправлять их по предсказаниям выбранной системы.
2. **Сохранить все отрицательные примеры.** Выборка задаётся входными метаданными, а не тем, на каких строках система сработала лучше. На следующих больших наборах брать фиксированные 500–1000 строк по хешу ID/текста с заранее заданным seed; не первые «удобные» строки.
3. **Сравнить три зафиксированных режима.** СЕЙФ rules-only, Presidio с русской моделью и СЕЙФ hybrid. Модель, threshold, mapping и post-processing объявляются до просмотра результатов. Иначе следующий результат является development-оценкой, для подтверждения которой нужен новый holdout.
4. **Разделить задачи.** `PERSON/EMAIL/PHONE/CARD` — сопоставимые типы; восемь близких типам задания меток HiveTrace — отдельный requirement-fit; NAME и ADDRESS — отдельные показатели. KPP/OGRN/OGRNIP/SNILS/TOKEN не превращаются в новые обязательные требования хакатона из-за их присутствия в корпусе. На срезе общих типов целые примеры выбираются по эталонной схеме до inference; количество исключённых строк публикуется.
5. **Не скрывать несовпадение схем.** NAME → PERSON (также CARDHOLDER у СЕЙФА), PHONE_NUMBER → PHONE, EMAIL → EMAIL, BANK_CARD_NUMBER → CARD, CVC → CVV, INN → INN, PASSPORT_NUMBER → PASSPORT, ADDRESS → ADDRESS. Границы полного адреса и его компонентов не сливаются по-разному для соперников. В текущем оценщике для ADDRESS отдельно публикуется диагностическое покрытие символов компонентами адреса/LOCATION; это proxy, а не exact-span F1 полного адреса. Любая агрегация задаётся заранее и публикуется дополнительно к сырому exact-span результату.
6. **Показать измеренную разницу.** Micro precision/recall/F1 и TP/FP/FN, показатели по типам и доменам, ошибки на отрицательных примерах. Для заявления об улучшении использовать парный bootstrap по примерам или документам с заранее заданным seed и интервалом для разницы F1; небольшой выигрыш без устойчивого интервала описывать как наблюдение, не доказанное превосходство.
7. **Проверить стоимость.** Detector latency после прогрева измеряется отдельно от HTTP `/v1/mask → /v1/unmask`, Redis, шифрования и нагрузки. Сравнение качества не отменяет требований к скорости, большим текстам, сохранению регистра и точному восстановлению.

Объективный критерий успеха — улучшение на заранее выбранном общем срезе без неприемлемого падения precision/recall на обязательных типах и без потери обратимости. Если на внешнем корпусе Presidio окажется лучше, результат сохраняется. Внешний benchmark не заменяет закрытую проверку организатора, а покрытие 95% нельзя выводить из числа пройденных собственных примеров.

Для будущего обучения пригодны только разрешённые train-части с проверенной историей происхождения. Текущий benchmark остаётся неизменным; российские паспорта, органы выдачи, даты рождения, публичный/личный контекст и регистр следует дополнять отдельным, заранее размеченным holdout по ТЗ, не превращая найденные ошибки этого теста в его же «независимое» улучшение.
