# Golden и первая итерация улучшения качества

## Общий скор и качество детектора

Два внешних ZIP содержат только агрегированный `scoring.log`: **9089 → 8868**,
замечания **103 → 130** (CRITICAL 77 → 97, MAJOR 24 → 26, MINOR 2 → 7).
Без правил, файлов, строк и формулы оценки нельзя установить причину падения
или интерпретировать эти числа как процент качества распознавания.

Детекторы `7a25c79` и `75b52e8`, до и после ревью, дали **одинаковые предсказания
на всех 446 текстах**, в обоих профилях и с одним замороженным NER-кешем.
Сам состав загруженного исходного архива вырос с 124 до 142 файлов, Python-код —
с 7242 до 10001 строк; поэтому счётчики замечаний также нельзя сравнивать как
проверку единственного изменения. Новый официальный скор требует повторной сдачи.

В текущей итерации обработка загрузки тела выделена в короткие методы:
цикломатическая сложность API Boundary снизилась с 20 до 6, NER Boundary —
с 21 до 9. Таймауты, освобождение памяти, статусы ошибок и запись запросов
проверены тестами. Правила анализатора не отключались.

## Неизменяемый набор

[`organizer-v1`](../datasets/golden/organizer-v1/README.md) содержит 446 уникальных
текстов, 469 размеченных сущностей, 369 положительных и 77 отрицательных примеров.
117 примеров имеют отметку неуверенной разметки. Это **provisional AI golden**:
разметка субагентов и независимое разрешение спорных случаев, а не официальный
эталон организатора и не подтверждённая человеком разметка.

Исходные тексты, метки, координаты и ожидаемые маски не менялись при улучшении
детектора. SHA-256 `cases.jsonl`:
`3bec44d5eafbffc799cd525bbe573f8b0adf84ec82e16271bd406fe92b521e46`.
Набор опубликован по явному разрешению пользователя в приватном репозитории.
Сырые HTTP-записи, адреса клиентов, ключи и runtime-файлы остаются под `.gitignore`.
Golden и NER-кеш исключены из ZIP сдачи и контекста сборки контейнера.

## Сравнение при неизменной разметке

Основная метрика — precision/recall/F1 защищённых буквенно-цифровых символов,
без требования одинаковой гранулярности соседних сущностей. Типизированные,
точные и взвешенные по трафику результаты сохранены отдельно.

| Метрика, hybrid, все 446 текстов | До | После |
|---|---:|---:|
| Precision | 80,98% | **93,44%** |
| Recall | 73,31% | **90,32%** |
| F1 | 76,95% | **91,85%** |
| Полностью совпавшие маски | 219 | **370** |
| Полностью защищённые положительные примеры | 208 / 369 | **316 / 369** |
| Отрицательные примеры с лишней маской | 31 / 77 | **18 / 77** |

F1 правил вырос с **67,97% до 86,95%**. На 329 примерах с уверенной разметкой
F1 hybrid составляет **98,00%**, но это дополнительный срез: основной результат
включает все 117 спорных примеров. Взвешенный по исходной частоте запросов
F1 hybrid — 91,77%. Ни один пример не потерял ранее защищённые символы эталона;
новых ложноположительных символов относительно baseline также нет.

Улучшения охватывают явные личные поля, инициалы и слитные ФИО, варианты дат,
серии/номера документов, PIN/CVV, органы выдачи и адреса регистрации. Подписи,
глаголы и корпоративные реквизиты отделяются от значений. Добавлены независимые
от golden отрицательные проверки и ограничения на рост времени регулярных
выражений. Ожидание старого авторского теста паспорта уточнено: слово «номер»
остаётся открытым; метки organizer-v1 не редактировались.

Это улучшение после просмотра корпуса, **не результат на новом holdout**.
Наш F1 не равен закрытой span-based Levenshtein метрике или общему скору хакатона;
выполнение официального требования 95% этим замером не установлено.

## Регрессии и работающий API

- **1173 теста прошли, 0 пропусков**, включая настоящий Redis и отказ primary
  с переключением Sentinel; Ruff и проверка diff прошли.
- Все **446 текстов** обработаны настоящим hybrid API: предсказания совпали с
  offline-оценкой, каждый текст восстановлен точно. Проверены также три демо
  во всех трёх режимах; подпись «Клиент:» остаётся видимой.
- Нагрузка **1000 заданных RPS, 60 секунд**: фактически 999,852 RPS,
  60 000 успешных запросов, 30 000 точно восстановленных пар, без ошибок,
  пропусков генератора и потерь записи. p95 **16,814 мс**, p99 **24,966 мс**,
  максимум **125,374 мс**; ответов дольше 500 мс нет.

Нагрузка измерена по loopback на отдельном стенде: 3 API-workers Python 3.14.7t
без GIL, 8 NER-workers, 3 Redis, 3 Sentinel, запись включена, смесь операций
50/50 на исходных 446 текстах. Это проверка регрессии, не новый пятиминутный
замер предела и не обещание той же задержки через Cloudflare.

В отдельной внешней пачке 11:57–12:02 UTC, ещё на предыдущей версии сервиса,
зарегистрировано 71 549 запросов, в том числе один 503 на этапе NER.
Организатор успешно повторил тот же запрос и выполнил восстановление.
Точная причина единичного сбоя из имеющихся логов не установлена.

Повторная проверка прежнего Scanpatch с неизменными текстами, метками и NER
дала на основном срезе 164 примеров F1 правил **49,67% → 52,07%**, hybrid
**68,98% → 69,01%**; Presidio остаётся выше — **72,53%**. По DOCUMENT+INN F1
снизился с 18,42% до 17,35%: один корпоративный десятизначный ИНН теперь открыт
по политике задания, а Scanpatch размечает его. Правила после этой проверки
не подгонялись. [Полный внешний отчёт](scanpatch-golden-regression.json).

## Воспроизведение

```bash
python scripts/evaluate_golden.py \
  --baseline benchmarks/golden/reference-v1.json \
  --output output/golden-quality/check.json
```

CI проверяет оба профиля относительно принятого улучшенного результата.
Исходный baseline `baseline-75b52e8.json` сохранён. Оценщик проверяет SHA-256
набора и NER-кеша, точное восстановление и отсутствие ухудшения P/R/F1 на полном
и уверенном срезах, а также число ложноположительных отрицательных примеров.
Существующие отчёты не перезаписываются. Offline-кеш позволяет проверять правила
без загрузки модели; доступность и скорость модели проверяются отдельно.
