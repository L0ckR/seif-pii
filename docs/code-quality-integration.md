## Что исправлено

Сложные обработчики API, детекторы и служебные скрипты разделены на функции с самостоятельными обязанностями. Сохранены порядок кандидатов, Unicode offsets, политика публичных реквизитов, deadlines, ограничения параллелизма и fail-closed поведение. Исправлена найденная при объединении ошибка, когда вновь созданная запись маскирования оставалась `None` у вызывающего кода.

Устранены перекрывающиеся обработчики `JSONDecodeError` в Redis CLI, повторяющиеся строки, неиспользуемые аргументы, сложные регулярные выражения и неоднозначная подготовка данных внутри `pytest.raises`. ASCII-цифры при упрощении regex сохранены через локальное `(?a:\d)`; замена на Unicode `\d` без ограничения не применялась. Для изменённых выражений выполнены дополнительные сравнения, включая 37449 вариантов окончаний поля выдачи документа.

Веб-интерфейс использует Web Crypto для резервной генерации идентификатора и JavaScript-модуль с ожидаемой инициализацией. Реальный Chromium проверил `/health`, `/v1/types`, маскирование, точное восстановление Unicode-текста с emoji и сообщение при отказе clipboard. Ошибок и предупреждений JavaScript нет; проверка работала через отдельный локальный API.

## Семь оставшихся замечаний Sonar

- **Два S2245** в `scripts/compare_presidio.py`: фиксированный генератор перемешивает benchmark-задания. Он не создаёт ключи, токены или секреты. Криптографический RNG нарушил бы воспроизводимость порядка.
- **Четыре S7503**: три асинхронных обработчика исключений NER-сервиса и endpoint типов API возвращают небольшие готовые ответы. FastAPI/Starlette отправляет синхронные обработчики в threadpool; текущая форма сохраняет непосредственную обработку в event loop. Искусственных `await` не добавлено.
- **Один S7513** в NER-клиенте: один синтаксический вызов `create_task` внутри comprehension создаёт несколько задач. Одиночный chunk обрабатывается раньше. Проверка четырёх одновременно запущенных chunks и отмены соседей при ошибке подтверждает необходимость TaskGroup.

Все семь остаются **OPEN в сыром экспорте**. Это документированные решения после проверки контекста, без сокрытия предупреждений и без заявления, что метка Sonar доказывает уязвимость.

## CI и полный диагностический экспорт

`ruff check seif tests scripts deploy` проходит с расширенным набором правил. Политика проекта явно допускает pytest assertions и фиктивные тестовые ключи, конкретные вызовы локальных программ без shell и seeded benchmark shuffle. Эти исключения ограничены нужными файлами и объяснены в `pyproject.toml`.

Отдельный `scripts/code_quality.py` запускает Ruff **с `--isolated`** на ZIP: настройки проекта не скрывают его замечания. Полные нативные GitLab JSON сохранены. В финальном security-экспорте 969 срабатываний: 942 pytest assertions, 17 тестовых credential literals, 8 запусков локальных программ и 2 seeded RNG. Runtime `seif/` — **0**; инструменты — 5, deployment — 1, тесты — 963. Рост числа assertions связан в том числе с дополнительными проверками и разделением составных утверждений; это не рост числа подтверждённых уязвимостей.

CI формирует ZIP и диагностические отчёты, применяет согласованную lint-политику и загружает отчёты даже при неуспехе последующих шагов. Golden gate использует принятый `reference-v2`, а не устаревший `reference-v1`. Тестовая матрица сохраняет Python 3.14 и 3.14t, Redis/Sentinel и проверки контейнеров/Kubernetes.

[Машиночитаемый отчёт](code-quality-integration.json) содержит версии, SHA, исходные количества и ссылки на доказательства. В архив доказательств не включены исходные тексты внешних корпусов, захваченные запросы, credentials и `.env`.

```bash
ruff check seif tests scripts deploy
SEIF_TEST_REDIS_URL=redis://127.0.0.1:6379/15 \
  SEIF_TEST_REDIS_SERVER=/usr/bin/redis-server pytest -q
python scripts/evaluate_golden.py \
  --baseline benchmarks/golden/reference-v2.json --output output/golden-quality/recheck.json
python scripts/package.py
python scripts/code_quality.py output/seif-pii-source.zip \
  --ruff ruff --output local-data/code-analysis/new-run
```

Для точного Sonar-повторения использовать сохранённые параметры и версии анализаторов. Native GitLab JSON совместим с форматом GitLab Code Quality; отдельный GitLab pipeline не запускался. Исходный ZIP для хакатона формируется без датасетов, capture-файлов, локальных отчётов, виртуальных окружений и секретов.
