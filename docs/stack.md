# Стек: Python 3.14 без GIL и отдельный NER

**Текущий выбор — Python 3.14.7t для API и правил, FastAPI/Uvicorn, Redis/Sentinel и отдельный Python 3.13.7 для необязательного Presidio PERSON/LOCATION NER.** Это уже реализованное разделение. Оно сохраняет проверенные русские правила и Unicode-смещения, позволяет параллельно обрабатывать большие документы и не привязывает основной сервис к тяжёлым NLP-зависимостям. Проверки и источники актуальны на 22 сентября 2026 года.

## Что исполняется где

| Компонент | Реализация | Причина |
|---|---|---|
| Основной API | CPython 3.14.7t, FastAPI/Uvicorn, несколько процессов | HTTP-конкурентность и независимость процессов; `/health` проверяет фактический GIL |
| Короткий текст | `detect()` в event loop | Передача короткого расчёта в пул имеет собственную стоимость |
| Более 16 000 символов | Ограниченный `ThreadPoolExecutor`, `SEIF_CPU_WORKERS` | Настоящее параллельное CPU-исполнение без GIL; слот занят до завершения работы, даже если HTTP отменён |
| Правила | `re`, контекст, checksums; `regex` для расширений с timeout | Российские поля ТЗ, ограниченные региональные форматы и адресная грамматика |
| Необязательный PERSON/LOCATION NER | Presidio 2.2.364, spaCy 3.8.16, ru_core_news_sm 3.8.0; Python 3.13.7 | Изолированные закреплённые зависимости и веса; модель не скачивается при запросе |
| Связь с NER | HTTPX по закрытой сети, общий ключ, ограниченные chunks/ответы/deadline | Проверка Unicode-границ и отказ без выдачи незащищённого успеха |
| Соответствия | Redis/Sentinel + AES-GCM + HMAC + TTL + атомарный `SET NX` | Общее состояние для workers; восстановление после переключения primary |

Код: [`app.py`](../seif/app.py), [`ner.py`](../seif/ner.py), [`ner_service.py`](../scripts/ner_service.py). Правила соседних стран и адресов не означают полноценную многоязычную модель: [региональные границы](cis.md), [адресный разбор](address-extraction.md).

## Измерение Python без GIL

Диагностическая серия: Linux/WSL2 x86-64, 16 логических CPU, по 20 000 вызовов `detect()` на четырёх синтетических текстах. Это ранняя версия правил и CPU-микробенчмарк без HTTP, Redis и NER.

| Runtime | 1 поток, вызовов/с | 4 потока, вызовов/с | 4 / 1 |
|---|---:|---:|---:|
| Обычный CPython 3.14.7 | 10 773 | 11 084 | 1,03× |
| CPython 3.14.7t, GIL выключен | 10 455 | 33 290 | **3,18×** |
| Та же 3.14.7t, GIL включён | 11 652 | 11 121 | 0,95× |

[3.14](runtime-314.json), [3.14t](runtime-314t.json), [3.14t с GIL](runtime-314t-gil.json). Однопоточное различие около 3% в одном запуске не доказывает стабильную величину; прирост четырёх потоков нельзя выдавать за ускорение HTTP в 3,18 раза.

Free-threading в Python 3.14 официально поддерживается, но остаётся **отдельной сборкой**. Обычная установка 3.14 сохраняет GIL. Неподготовленное нативное расширение может включить его обратно: проверяются и `Py_GIL_DISABLED`, и `sys._is_gil_enabled()` после реальных импортов. [Статус Python 3.14](https://docs.python.org/3.14/whatsnew/3.14.html#free-threaded-python-is-officially-supported), [руководство](https://docs.python.org/3.14/howto/free-threading-python.html).

**Один event loop не распределяет синхронные CPU-задачи по ядрам.** Для этого нужен явный executor либо несколько процессов. Поэтому короткие запросы основного стенда обслуживают несколько Uvicorn-workers, а большие — ещё и ограниченный пул. [Блокирующий код в asyncio](https://docs.python.org/3.14/library/asyncio-dev.html#running-blocking-code), [asyncio.to_thread](https://docs.python.org/3.14/library/asyncio-task.html#asyncio.to_thread), [Uvicorn workers](https://uvicorn.dev/deployment/#built-in).

## Совместимость и NER

В проверенном 3.14t GIL оставался выключенным после FastAPI, `pydantic_core`, реального AES-GCM из `cryptography`, `regex`, PyYAML, Redis, uvloop и httptools. Для закреплённых версий подтверждены Linux x86-64 `cp314t` wheels: [pydantic-core 2.46.5](https://pypi.org/pypi/pydantic-core/2.46.5/json), [cryptography 50.0.1](https://pypi.org/pypi/cryptography/50.0.1/json), [regex 2026.9.10](https://pypi.org/pypi/regex/2026.9.10/json), [PyYAML 6.0.3](https://pypi.org/pypi/PyYAML/6.0.3/json), [uvloop 0.22.1](https://pypi.org/pypi/uvloop/0.22.1/json), [httptools 0.8.0](https://pypi.org/pypi/httptools/0.8.0/json).

Наличие wheel не заменяет проверку конкурентного поведения. [Python: требования к расширениям](https://docs.python.org/3.14/howto/free-threading-extensions.html). CI запускает функциональный набор на обычном 3.14 и 3.14t; актуальное число тестов и финальные прогоны находятся в [validation.md](validation.md). Режим `SEIF_REQUIRE_FREE_THREADING=1` отклоняет запуск без требуемой сборки или при включённом GIL.

NER проверен отдельно на обычном Python 3.13.7; из этого не следует, что вся экосистема spaCy несовместима с 3.14t. Это выбранная и воспроизводимо установленная конфигурация. В NER-сервисе оставлены `tok2vec + ner`, отключены ненужные синтаксические и морфологические этапы. Предшествующее измерение оптимизации выполнено для PERSON-only. На 76 собственных примерах типы/границы/score совпали; среднее время вызова снизилось **4,064 → 2,752 мс**, p95 **6,123 → 3,738 мс**. [Результат](ner-pipeline-optimization.json). За пределами этих 76 примеров полная эквивалентность не заявляется.

У NER один выполняющий расчёт поток на worker и ограниченная очередь; процессы масштабируются отдельно. Нагрузка NLP не исполняется в event loop основного API. Дополнительный тип `LOCATION` сохраняет географическую семантику модели; он не заменяет `CITY` или полный личный `ADDRESS`. Закреплённые зависимости: [основной lock](../requirements.lock), [NER lock](../deploy/ner/requirements-ner.txt).

## Качество и HTTP — разные измерения

Первый внешний HiveTrace прогон замороженной версии до новой адресной грамматики: на `domain/common4` F1 правил **99,20%**, Presidio RU **96,26%**, hybrid **97,36%**; у hybrid выше recall, но больше ложных срабатываний. На восьми близких ТЗ типах и адресах результат существенно ниже. Это причина сохранять два профиля и измерять изменения на новых данных. [Полное сравнение](presidio.md), [корпуса](datasets.md).

Финальная HTTP-серия правил с тремя API-workers и Sentinel дала **2099,33 успешных RPS за 300 с**, p95 **13,523 мс**, максимум **258,875 мс**. 629 814 ответов 200; генератор пропустил 93 пары при лимите 128. PERSON/LOCATION hybrid с тремя API и восемью NER-workers дал **1049,54 RPS за 300 с**, 315 000 ответов 200, p95 **73,799 мс**, максимум **481,792 мс**, без ошибок и пропусков. На этих коротких синтетических текстах выполнен новый ориентир 0,5 с; результат не переносится на другие размеры, оборудование и публичный туннель. [Подробности и исходные JSON](validation.md).

Несколько процессов требуют общего Redis, одинакового мастер-ключа и политик: маскирование и восстановление могут попасть в разные workers. Пул внутри процесса не делает произвольное разделяемое состояние потокобезопасным; счётчики приложения изменяются в принадлежащем им event loop. [Python: thread safety](https://docs.python.org/3.14/howto/free-threading-python.html#thread-safety).

## Почему пока не Go

Go предоставляет CPU-параллелизм и стандартный `regexp` с линейным временем поиска; это сильные свойства для сервиса недоверенного текста. Они не доказывают ускорение конкретного детектора. [GOMAXPROCS](https://pkg.go.dev/runtime#GOMAXPROCS), [Go regexp](https://pkg.go.dev/regexp).

| Цена переноса | Что придётся проверить |
|---|---|
| Lookaround | Правила используют lookahead/lookbehind; RE2 их не поддерживает. Понадобится переработка границ и контекста. [RE2 syntax](https://github.com/google/re2/wiki/Syntax) |
| Unicode | Go `\w`, `\d`, `\s`, `\b` имеют ASCII-семантику; Python строковые шаблоны учитывают Unicode. Прямой перенос меняет русские границы. [Go syntax](https://pkg.go.dev/regexp/syntax), [Python re](https://docs.python.org/3.14/library/re.html#regular-expression-syntax) |
| Смещения | Go возвращает байтовые индексы UTF-8, API СЕЙФА — Unicode code points; нужна конверсия и тесты emoji/кириллицы. [Индексы Go](https://pkg.go.dev/regexp#pkg-overview) |
| Зависимости и политика | NLP всё равно требует модели; пользовательские regex, публичные исключения, пересечения и восстановление должны сохранить поведение |

Переход оправдан, когда профиль покажет устойчивую стоимость CPU/памяти, текущие процессы и bounded pools не укладываются в целевую цену, а прототип на Go сохраняет качество на тех же данных. Сейчас измерения обосновывают работающую Python-архитектуру и отдельное масштабирование NER; обещать выигрыш переписывания без такого сравнения было бы предположением.
