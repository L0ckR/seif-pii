# Оценка качества и нагрузки на разрешённом локальном корпусе

Исходные данные, разметка, ответы сервиса и журналы экспериментальных запросов
хранятся только в `local-data/`. Этот каталог исключён из Git, Docker и ZIP.
Публикуемые инструменты не содержат текстов организаторов и не скачивают их.

## Разметка

Перед оценкой фиксируются исходники, версия детектора, предсказания и протокол.
Первичный разметчик получает только оригиналы и правила: типы ПД, исключения для
публичного контекста, границы значений и порядок пометки неопределённости.
Предсказания ему не показываются. Второй разметчик проверяет заранее выбранную
подвыборку; спорные решения разбираются отдельно без доступа к выходам детектора.
Первичные файлы сохраняются, исправленная разметка получает отдельную версию.

Разметка ИИ является предварительной. Даже совпадение двух разметчиков не делает
её эталоном организаторов. После анализа и настройки на корпусе он считается
данными разработки, а для независимой проверки нужен новый набор.

`scripts/evaluate_annotations.py` сопоставляет точные Unicode-spans с замороженными
предсказаниями. Основная метрика — precision/recall/F1 защищаемых буквенно-цифровых
позиций; пробелы и пунктуация не должны маскироваться. Отдельно показываются
полностью защищённые положительные примеры, лишнее маскирование отрицательных,
покрытие типов, результаты без неоднозначных случаев и с весами частоты запросов.
Проверяются полнота набора, совпадение подстрок с offsets, отсутствие пересечений
и соответствие сохранённой маски предсказанным spans.

```bash
.venv/bin/python scripts/evaluate_annotations.py \
  --inputs local-data/evaluation/input-only.jsonl \
  --annotations local-data/evaluation/annotations-adjudicated.jsonl \
  --predictions local-data/evaluation/frozen-predictions.jsonl \
  --corpus local-data/evaluation/load-corpus.jsonl \
  --output local-data/evaluation/quality.json
```

Это не реализация закрытой span-based метрики Левенштейна организаторов: их
эталоны и точная реализация неизвестны. Нельзя подменять официальный балл нашим F1.

## Нагрузка

`scripts/benchmark_corpus.py` принимает JSONL с `case_id`, исходным `payload`
и положительным `weight`. Сначала можно проверить файл через `--prepare-only`.
Генератор допускает только выделенный loopback endpoint и блокирует известные
порты публичного стенда. Корпус должен оставаться в разрешённом локальном контуре.

```bash
.venv/bin/python scripts/benchmark_corpus.py \
  --corpus local-data/evaluation/load-corpus.jsonl \
  --protocol local-data/evaluation/capacity-protocol.json \
  --url http://127.0.0.1:8966 --rps 1000 --duration 300 \
  --concurrency 256 --seed 20260922 \
  --output local-data/evaluation/capacity-1000.json
```

Если нужны ключи системы, задайте одновременно `SEIF_BENCH_SYSTEM` и
`SEIF_BENCH_API_KEY` в окружении. Не передавайте ключи аргументами командной строки.

`--rps` — предложенное число HTTP-запросов в секунду: пара состоит из маскирования
и обратного запроса. Для каждой пары создаётся новый ID, ответ проверяется на
точное совпадение с оригиналом. Скрытых ретраев нет. Пропуски из-за заполненной
очереди клиента или отставания расписания явно учитываются. Вторая часть пары
зависит от первой; неотправленные вторые запросы не считаются успешной нагрузкой.

Сначала выполняются короткие ступени нагрузки, затем длительное подтверждение
выбранной скорости. Критерий успеха задаётся заранее: все пары проверены,
нет ошибок и пропусков, фактическая скорость достигает целевой в заданном допуске,
выполняется выбранное ограничение задержки. При строгом лимите 0,5 с нужно учитывать
максимум и число превышений, а не только p95. Для записи запросов дополнительно
проверяются её очередь, `dropped`, `write_errors` и число сохранённых записей.

Отчёт хранит хеш корпуса и протокола, версии, распределение запросов, фактический
RPS, p50/p95/p99/максимум, превышения 500/1000 мс и ошибки. Исходных текстов,
case IDs, payload IDs и секретов в отчёте нет. Старый отчёт не перезаписывается.

Изолированный стенд должен воспроизводить рабочие API/NER-workers, Redis,
репликацию и режим записи. Изменения лимита RPS для поиска вычислительного предела
обязательно отражаются в протоколе. Нагрузка на loopback не подтверждает скорость
через Cloudflare; результаты одного хоста не доказывают доступность нескольких
узлов. Точность восстановления не заменяет оценку распознавания ПД.
