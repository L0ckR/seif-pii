## Проверка пяти BUG/VULNERABILITY

Подробности, строки, probes и ограничения — в [отчёте triage](code-analysis-triage.md) и [машиночитаемом triage](code-analysis-triage.json).

- `scripts/local_redis.py:274`, `S1045`: подтверждён небольшой дефект служебного CLI. `JSONDecodeError` наследует `ValueError`, поэтому более общий ранний обработчик перехватывает его и выдаёт другое сообщение. Это не дефект детекции ПД.
- `scripts/compare_presidio.py:239,242`, `S2245`: seeded RNG перемешивает порядок бенчмарка. Здесь случайность служит воспроизводимости, а не защите секретов.
- `web/app.js:58`, `S2245`: fallback `Math.random` для `payload_id` стоит заменить на Web Crypto. Обычная HTTPS-ветка использует `crypto.randomUUID`. Практическая атака или утечка не подтверждались.
- `seif/ner.py:136`, `S7490`: вероятное ложное срабатывание про timeout без checkpoint. Выход `asyncio.TaskGroup` неявно ожидает задачи; проверка с лимитом 25 мс завершилась за 25,84 мс, все четыре задачи выполнили `finally`.

Повторно прошли **38 существующих целевых тестов**: deadline/cancellation/privacy и adversarial/custom-regex. Это проверка конкретных рисков, не доказательство отсутствия всех возможных уязвимостей. Production-код в рамках этих прогонов не изменялся.

## GitLab Code Quality

[GitLab Code Quality](https://docs.gitlab.com/ci/testing/code_quality/) принимает отчёты разных анализаторов; сам формат не определяет набор правил. Выполнен локальный **Ruff 0.16.8 с нативным `--output-format gitlab`**, который [документирован GitLab](https://docs.gitlab.com/ci/testing/code_quality/#ruff). Pipeline на GitLab и старый CodeClimate engine не запускались.

| Фиксированный профиль Ruff | original | reviewed | golden |
|---|---:|---:|---:|
| Правила проекта: `E4,E7,E9,F,I,B` | 8 | 0 | 0 |
| Поддерживаемость: `C901,C4,SIM,PERF,PLR0911,PLR0912,PLR0913,PLR0915` | 54 | 70 | 68 |
| Security: `S`, сырые срабатывания | 429 | 657 | 797 |

В последней строке **788 из 797** относятся к тестам; главный источник — `assert`. Это не 797 подтверждённых уязвимостей. Нативный экспорт Ruff классифицировал все замечания как `major`; эти severity нельзя сопоставлять с Sonar или внешним скором. Профили диагностические, с фиксированными правилами и стандартными порогами Ruff; inline `noqa` сохраняется. Никаких автоматических исправлений не выполнялось.

Добавлен воспроизводимый локальный runner [scripts/code_quality.py](../scripts/code_quality.py). Он анализирует все `.py` под `seif/`, `scripts/`, `tests/`, `deploy/` в исходном ZIP, проверяет пути и структуру GitLab JSON и сохраняет SHA исходников. Архив не исполняется. Каждый запуск требует нового каталога результатов:

```bash
.venv/bin/python scripts/code_quality.py /path/to/seif-pii-golden-4c85827.zip \
  --ruff .venv/bin/ruff --output local-data/code-analysis/gitlab/new-run
```

В каждом каталоге сохраняются три `*.gitlab.json` и `summary.json`. Эти JSON можно передавать как GitLab `artifacts:reports:codequality`; название профиля и его состав следует указывать явно.

Runner прошёл 19 тестов, включая защиту от пропуска файлов встроенными исключениями Ruff и от коллизий fingerprint; проверка Ruff проекта также прошла. После независимого аудита runner повторно обработал все три ZIP: девять native GitLab JSON побайтово совпали с первым запуском.

## Что это говорит о падении внешнего скора

В присланных логах: **9089 → 8868**, замечаний **103 → 130**, CRITICAL **77 → 97**. Локальный Sonar воспроизвёл направление изменения, **но не сами числа**: для первых двух ZIP 66 → 94 и 30 → 40 CRITICAL. Версия движка, правила, формула скора и SHA проверенного архива в логах отсутствуют. Совпадение направлений не доказывает, что организаторы используют именно этот SonarQube.

Между первыми ZIP объём Python вырос с 7242 до 10001 физических строк (+38,1%); между вторым и третьим — до 11960. Поэтому сравнение отражает одновременно изменения кода и расширение области проверки. В локальном Sonar число замечаний выросло и в runtime, и в инструментах, и в тестах. Нельзя приписать весь прирост одному рефакторингу либо объяснить его только тестами.

Для golden-версии ранее измеренное улучшение качества распознавания и увеличение числа замечаний Sonar могут существовать одновременно: эти проверки измеряют разные свойства решения. Перед дальнейшим рефакторингом нужно сохранять golden-предсказания, а не оптимизировать один показатель за счёт другого.

## Воспроизводимость и артефакты

[code-analysis.json](code-analysis.json) содержит SHA трёх архивов, версии анализаторов, параметры и сводки всех шести прогонов, списки замечаний трёх версий и сравнение Ruff. Полный локальный экспорт API и native GitLab JSON сохранены под `local-data/code-analysis/`; каталог исключён из Git.

Sonar работал на локальном сервере `127.0.0.1:19000` с частными проектами и отключённой telemetry. Анализировались отдельные копии исходных ZIP. Организаторский датасет, HTTP-захваты, `.env` и рабочие каталоги результатов в анализ не передавались. Пароли и токен Sonar находятся только в игнорируемом локальном каталоге.

После экспорта сервер Sonar штатно остановлен, чтобы освободить ресурсы машине с рабочим API. Отчёты и локальная база Sonar сохранены; процессы API и NER продолжают работать.

Для повторения Sonar нужен сервер указанной версии со стандартным Sonar way и Scanner CLI указанной версии. В новой копии исходного ZIP:

```bash
# SONAR_TOKEN задаётся через окружение, не через аргументы или Git.
sonar-scanner \
  -Dsonar.host.url=http://127.0.0.1:19000 \
  -Dsonar.projectKey=seif-golden-recheck \
  -Dsonar.projectVersion=4c85827 \
  -Dsonar.sources=. \
  -Dsonar.sourceEncoding=UTF-8 \
  -Dsonar.python.version=3.14 \
  -Dsonar.scm.disabled=true \
  -Dsonar.scanner.skipJreProvisioning=true
```

Для второго режима добавить `-Dsonar.tests=tests '-Dsonar.exclusions=tests/**'`, используя другой project key. Эти параметры [классифицируют source и test отдельно](https://docs.sonarsource.com/sonarqube-server/project-administration/adjusting-analysis/setting-analysis-scope/setting-initial-scope); тесты не удаляются из анализа. Для повторения исходного эксперимента не добавлять в снимок новые файлы этого отчёта и диагностического runner.
