## Семь исправлений

Два замечания к RNG устранены заменой перемешивания в сравнительном CPU-бенчмарке на детерминированное ранжирование по SHA-256. В отчёте записаны алгоритм `sha256-rank-v1`, seed и порядок исходных данных. Все примеры и системы по-прежнему получают одинаковое число вызовов; хеширование выполняется за границей измеряемого вызова. Исторические времена не пересчитаны и не объявлены полученными в новом порядке. Код расчёта качества не изменён; устаревшее исключение Ruff S311 для этого файла удалено.

Одно замечание к TaskGroup устранено явным циклом создания задач. Отдельные тесты подтверждают параллельный запуск четырёх частей, исходный порядок результата, отмену соседей при ошибке и выполнение одиночной части в текущей задаче.

Четыре служебных callback используют небольшой внутренний [адаптер](../seif/async_callbacks.py): `inspect.markcoroutinefunction` сообщает фреймворку, что результат нужно ожидать, а готовый Future завершает ожидание сразу. Вычисление остаётся на текущем event loop, без новой задачи, искусственного `sleep` или worker thread. Сигнатура и привязка `self` сохранены; результат и исходные исключения не подменяются. Он предназначен только для ограниченных неблокирующих callback вида `await callback(...)`; возвращаемый Future не является coroutine для `create_task`.

Адаптер применяется только к `/v1/types` и трём обработчикам ошибок NER. Успешная обработка `/process`, маскирование и модельный анализ сохраняют обычные асинхронные обработчики. В NER Dockerfile включён общий модуль; отдельная проверка изолированной структуры образа на Python **3.13.7** подтвердила импорт, health, успешный analyze, ответы 422/404 и отсутствие threadpool для ошибок. Полный образ проверяет существующий CI.

## Цена по скорости

Первый вариант с обычными синхронными обработчиками **отклонён**: он добавлял около 170–240 мкс для типов и основных NER-ошибок. В итоговом варианте этого перехода в пул потоков нет.

Микрозамер прототипа дал **+0,374 мкс** на непосредственное ожидание одного затронутого callback против исходного native async; это одна дополнительная аллокация Future. Нулевая стоимость или ускорение не заявляются. В двух последовательных ASGI-прогонах `/v1/types` получил +2,9/+5,4 мкс; NER-ошибки колебались в обе стороны. Код прототипа адаптера совпадает по поведению с проверенным production-модулем; интеграционные тесты проверяют реальную диспетчеризацию.

Для неизменённого `/process` медиана локального ASGI-прогона изменилась на **+0,16% / −1,71%**. Эти короткие замеры со stub NER и in-memory vault не устанавливают причинность, максимальный RPS или производительность под конкурентной сетевой нагрузкой. В них нет прежней систематической цены threadpool; доказательство неизменности основного пути дополняется сравнением исходников. Полные измерения, ограничения и воспроизводимые скрипты сохранены.
