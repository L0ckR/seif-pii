# СЕЙФ и Presidio: измерения, интеграция и ограничения

**Общее превосходство над Presidio не подтверждено.** На первом внешнем русском PII-Bench профиль правил выиграл сопоставимый срез; на следующем независимом Red Mad Robot выбранная русская конфигурация Presidio оказалась существенно лучше. PERSON-гибрид улучшает имена, но не компенсирует пропуски пространственных сущностей. Оба первых отчёта сохранены без изменения.

Presidio интегрирован как необязательный локальный источник NER-кандидатов. Финальный hybrid добавляет **PERSON и LOCATION**; первые HiveTrace и Red Mad Robot измеряли более ранний PERSON-only вариант. Правила для банковского ТЗ, обратимый vault и API проверяются отдельно от качества модели.

Ниже сравнивается конкретная воспроизводимая конфигурация Presidio, а не предел возможностей фреймворка. Исследование и первый внешний прогон выполнены 22 сентября 2026 года. Presidio создан Microsoft; сейчас проект объявил переход к управлению сообществом Data Privacy Stack с сохранением MIT. [Официальное объявление](https://presidio.dataprivacystack.org/project_transition/).

## Финальная проверка: Scanpatch, смешанный RU/UK

Последний ранее не использованный [test Scanpatch](https://huggingface.co/datasets/scanpatch/pii-ner-corpus-synthetic-controlled/blob/6af0587dde068d90d8a1080285159c374b46a09b/README.md) содержит **532** синтетических документа с разметкой LLM по проверенным правилам. Все исходные spans прошли проверку; метки не исправлялись. Язык каждой строки не указан, поэтому результат относится только к смешанному RU/UK-набору. Presidio у всех вариантов использует ту же **русскую** модель, не специально настроенную украинскую конфигурацию.

До inference заморожены код `732dabbdfbec9b37727e247481958a7dbc157cc1cb53409231bf9398100c1508`, mapping и симметричное объединение вложенных/смежных меток. Общий срез: **164 целых примера, 58 отрицательных**. Схема common5 содержит PERSON/LOCATION/EMAIL/PHONE/CARD, но **CARD в корпусе отсутствует**: положительно проверяются четыре типа.

| Детектор | Precision символов | Recall символов | F1 символов — основной | Exact-span F1 — дополнительный |
|---|---:|---:|---:|---:|
| СЕЙФ, правила | **84,04%** | 35,25% | 49,67% | 38,88% |
| Presidio RU | 82,95% | **64,44%** | **72,53%** | **62,32%** |
| СЕЙФ, PERSON+LOCATION hybrid | 78,25% | 61,67% | 68,98% | 57,99% |

95%-интервал разницы основного F1 hybrid−Presidio — **−8,35…+0,41 п.п.**: преимущества гибрида не доказано, интервал включает ноль. Для дополнительного exact-span F1 интервал **−7,64…−1,21 п.п.** находится ниже нуля. На всех 532 строках F1 символов PERSON составляет 56,43% / 71,33% / 71,91%, LOCATION — 13,30% / 35,97% / 36,84% (правила / Presidio / hybrid). Небольшой выигрыш отдельных общих категорий не превращается в выигрыш на заранее выбранном основном срезе.

Полный неизменяемый первый результат — [`scanpatch-comparison.json`](scanpatch-comparison.json), оценщик — [`evaluate_scanpatch.py`](../scripts/evaluate_scanpatch.py). После этой оценки правила, модели и пороги больше не подгонялись. Это не доказательство полного покрытия языков СНГ, банковского ТЗ или реального трафика.

Отдельная **диагностика после разработки** на сохранённых Red Mad Robot PERSON/LOCATION-предсказаниях дала новому гибриду F1 символов **68,44%** против прежних 52,41% PERSON-only и 62,34% Presidio; exact-span F1 — 54,76%. Поскольку архитектура выбрана по результатам этого корпуса, улучшение **не является новым blind-результатом**. Исходный отчёт не менялся; новые числа находятся в [`redmadrobot-location-ablation.json`](redmadrobot-location-ablation.json). Базовые правила на всех 2 839 строках остались теми же; новая NLP-inference не выполнялась.

## Второй независимый тест: Red Mad Robot, PERSON-only версия

После адресной доработки выбран ранее не использованный [русский test Red Mad Robot](https://huggingface.co/datasets/redmadrobot-rnd/pii_benchmark/blob/f77ea831274daf980cc45c61a93c226be9d978d6/README.md), MIT: 2 841 строка, 21 тип BIO-разметки. До inference исключены `row_0000` и `row_1628`, чьи токены не выравниваются с исходным текстом буквально. Все три системы получили **2 839** строк. Разработчик адресных правил не читал примеры этого теста; SHA-256 детектора — `c45e8f6106ea0f7c3c1cf8358c93a7ce2592a1f9b28a226afaa0ac9868ce4c31`.

Общий срез содержит **1 237 целых строк, включая 371 отрицательную**: PERSON, LOCATION, EMAIL, PHONE, CARD. Имя приведено из FIRST/LAST/MIDDLE_NAME, LOCATION — из шести адресных компонентов. Одинаковые категории объединяются при пересечении или только пробельном промежутке на обеих сторонах; запятые и текст не нормализуются. Основная метрика — покрытие **символов с правильным типом**; точное совпадение объединённых spans приводится отдельно.

| Детектор | Precision символов | Recall символов | F1 символов — основной | Exact-span F1 — дополнительный |
|---|---:|---:|---:|---:|
| СЕЙФ, правила | **94,72%** | 30,61% | 46,27% | 30,95% |
| Presidio RU | 83,75% | **49,65%** | **62,34%** | **53,91%** |
| СЕЙФ, PERSON-hybrid | 84,38% | 38,01% | 52,41% | 37,70% |

95%-интервал парной разницы F1 символов с Presidio: **правила −19,77…−12,42 п.п.; PERSON-hybrid −13,05…−6,90 п.п.** Выполнено 2 000 повторов с фиксированным seed. Доменной разметки здесь нет: bootstrap использует одну группу всех выбранных строк. Отставание устойчиво в рамках этого протокола.

| Диагностика на всех 2 839 строках, F1 символов | Правила | Presidio RU | PERSON-hybrid |
|---|---:|---:|---:|
| PERSON | 45,80% | 63,01% | **67,46%** |
| LOCATION | 32,02% | **65,67%** | 32,02% |

У PERSON полнота гибрида **62,76%** против 57,19% Presidio: объединение имён полезно. Главное отставание — LOCATION: полнота правил **21,50%**, Presidio **51,39%**. LOCATION означает пространственную NER-категорию, а не гарантированно полный личный почтовый адрес. Результат обосновывает отдельный LOCATION-канал, но его добавление уже будет разработкой после просмотра данного теста и потребует нового holdout.

Первый отчёт — [`redmadrobot-comparison.json`](redmadrobot-comparison.json), оценщик — [`evaluate_redmadrobot.py`](../scripts/evaluate_redmadrobot.py). Его числа нельзя сопоставлять с leaderboard издателя: там используются overlap matching и подобранные пороги. Версии модели, threshold и исходный текст в нашем прогоне не менялись. Latency этого прогона не публикуется как SLA.

## Первый внешний результат: HiveTrace

[HiveTrace PII-Bench](https://huggingface.co/datasets/hivetrace/pii-bench) — внешний синтетический русский набор с ручной проверкой. Оценены все **1 810** строк двух splits без исправления разметки. Детектор заморожен до inference: SHA-256 `d3a66e2de0a42beb34c411504e1187d0ae1b0f280291084d040a10269480980b`. Этот отчёт относится к указанной версии; последующие адресные изменения не подменяют её результаты.

Основной срез `domain/common4`: **612 целых примеров, 315 сущностей, 378 отрицательных примеров**. Общие типы — NAME/PERSON, EMAIL, PHONE, CARD. Включались все примеры, чья эталонная схема ограничена этими типами, и все пустые; отбор не зависел от предсказаний. Засчитывается точное совпадение типа и обеих символьных границ.

| Детектор | Precision | Recall | F1 | TP / FP / FN |
|---|---:|---:|---:|---:|
| СЕЙФ, правила | **100,00%** | 98,41% | **99,20%** | 310 / 0 / 5 |
| Presidio + русская модель | 94,50% | 98,10% | 96,26% | 309 / 18 / 6 |
| СЕЙФ hybrid | 95,15% | **99,68%** | 97,36% | 314 / 16 / 1 |

Парный bootstrap: 2 000 повторов, стратификация по доменам, заранее закреплённый seed. 95%-интервал разницы F1 относительно Presidio: **правила +1,28…+4,80 п.п.; гибрид +0,17…+2,29 п.п.** На этом срезе оба режима имеют положительную разницу. Интервалы условны: они не моделируют зависимость синтетических шаблонов и не означают такой же выигрыш на банковском production-трафике.

На другом split, `entity/common4` — 280 примеров без отрицательных — F1 правил **98,37%**, Presidio и гибрида **98,07%**. Интервал разницы правил −1,17…+1,72 п.п. включает ноль: убедительного преимущества здесь нет.

Источник чисел, версий, checksum и ограниченных диапазонов ошибок без исходных текстов — [`pii-bench-comparison.json`](pii-bench-comparison.json); оценщик — [`evaluate_external.py`](../scripts/evaluate_external.py). Источники и условия данных: [datasets.md](datasets.md).

## Что за общим F1

| Диагностика на `domain` | Правила | Presidio RU | Hybrid | Значение |
|---|---:|---:|---:|---|
| NAME, F1 на всех 900 примерах | 96,05% | 84,90% | 88,30% | Модель добавляет имена, но также ложные срабатывания |
| NAME, recall | 92,41% | 94,30% | **95,57%** | У гибрида 7 пропусков вместо 12 у правил |
| Покрытие 8 близких ТЗ типов, F1 | 85,77% | 74,59% | 84,06% | Диагностика разных возможностей, не общий рейтинг NER |
| ADDRESS, exact-span F1 компонентов/LOCATION proxy | 8,14% | 10,23% | 8,14% | Полный адрес и его компоненты имеют разные границы |
| ADDRESS, F1 покрытия символов | 64,81% | 46,63% | 64,81% | Даже с учётом компонентов покрытие недостаточно |

**Свободно записанные адреса — реальный пробел.** У этой версии правил recall адресных символов лишь **52,30%**. Низкое exact-span качество нельзя объяснить только разметкой компонентов: значительная часть адреса остаётся незащищённой. После этого разработана отдельная адресная грамматика и выполнен описанный выше независимый Red Mad Robot; достаточное покрытие LOCATION не подтверждено. Повтор HiveTrace после изменения будет development-диагностикой, а не новым независимым доказательством.

Срез восьми типов содержит 787 примеров и включает паспорт, ИНН, CVC и ADDRESS, для которых baseline не имеет всех нужных русских recognizers. Пять меток корпуса — KPP/OGRN/OGRNIP/SNILS/TOKEN — вне схемы задания; в полном отчёте они явно указаны как неподдержанные.

Конкретный пробел стандартного recognizer: четыре пропущенные карты Presidio в `domain/common4` имеют префикс `22` и корректный Luhn; проверенный upstream-шаблон допускает начальные 1/3/4/5/6, но не 2. Поддержка такого российского формата полезна, однако пользовательский recognizer может добавить её и в Presidio. [Проверенный исходник CreditCardRecognizer](https://github.com/data-privacy-stack/presidio/blob/33586b8dc7308cd15427b60764f9e8c1163463c2/presidio-analyzer/presidio_analyzer/predefined_recognizers/generic/credit_card_recognizer.py).

## Конфигурация и честность сравнения

Presidio Analyzer **2.2.364**, spaCy **3.8.16**, **ru_core_news_sm 3.8.0**; Spacy/Email/Phone/CreditCard/Date recognizers настроены для `ru`, с русскими контекстными словами и регионом RU для телефона. Upstream-шаблоны, проверки и веса не менялись; threshold **0.0** закреплён до измерения. Русские тексты не сравнивались со стандартным английским baseline. [Подключение языков](https://presidio.dataprivacystack.org/analyzer/languages/), [модель](https://github.com/explosion/spacy-models/releases/tag/ru_core_news_sm-3.8.0).

Все три варианта внешней оценки работают в одном обычном CPython **3.13.7**. Для абляции hybrid объединяет правила с теми же PERSON-предсказаниями Presidio. Это измерение качества детектора; оно не включает HTTP, очередь модели, Redis и шифрование. Разметка внешнего автора сохранена, даже когда его понятие ПД расходится с политикой задания о публичном лице или адресе организации.

Предыдущее малое сравнение хранится в [`presidio-comparison.json`](presidio-comparison.json): до регионального расширения свежий общий срез из 23 сценариев/17 сущностей дал F1 86,67% правил против 88,89% Presidio. Модель находила непривычные имена, которые правила пропускали. Это объясняет добавление гибрида; результаты разных версий и корпусов нельзя смешивать в одну таблицу прогресса.

## Как соотносятся архитектуры

| Возможность | Presidio | СЕЙФ |
|---|---|---|
| Расширение поиска | Реестр recognizers, regex, модели, NLP adapters | 24 типа ТЗ и отдельная LOCATION-категория, банковские правила, опциональные PERSON/LOCATION-кандидаты Presidio |
| Языки и страны | Подключаемые модели и национальные recognizers | Русский профиль; ограниченные идентификаторы семи соседних регионов, см. [границы](cis.md) |
| Контекст | `ContextAwareEnhancer`, леммы, score, allow-lists | Контекст конкретного поля и публичные исключения по политике |
| Преобразование | Anonymizer с заменой, mask/hash/encrypt и пользовательскими операторами | Mask/token/synthetic, обратимое соответствие всех режимов |
| Восстановление | `DeanonymizeEngine` для поддерживаемых операторов; mapping можно добавить | AES-GCM vault, TTL, система + payload_id, повторы и перестановка известных LLM-токенов |
| Эксплуатация | Библиотеки и HTTP-компоненты для приложения | API-ключи, политики, лимиты, метрики, Redis/Sentinel, Compose и Kustomize |

`AnalyzerEngine` отделяет кандидатов от преобразования; `AnonymizerEngine` разрешает пересечения и применяет операторы. Это удачные точки расширения, особенно для новых моделей и национальных форматов. Но `DATE_TIME` не различает рождение и выдачу паспорта, а `LOCATION` не гарантирует полный почтовый адрес. [Analyzer](https://presidio.dataprivacystack.org/analyzer/), [Anonymizer](https://presidio.dataprivacystack.org/anonymizer/), [каталог типов](https://presidio.dataprivacystack.org/supported_entities/).

**Обратимость есть у обоих решений.** Presidio имеет [encrypt/decrypt](https://presidio.dataprivacystack.org/tutorial/12_encryption/) и [пример mapping-псевдонимизации](https://presidio.dataprivacystack.org/samples/python/pseudonymization/). Наше дополнение — прикладное хранение соответствий и scope, а не изобретение обратимости. Асинхронная репликация Redis допускает потерю части последних соответствий при аварии; это описано в [runbook](kubernetes.md#границы-сохранности-и-обслуживания).

## Что перенесено и что уже работает

Две идеи реализованы самостоятельно: ограниченный контекст конкретного поля и разделение проверки номера от исключения ложного контекста. Упоминание паспорта больше не распространяется через завершённое предложение на дату выдачи товара; валидный по checksum номер заказа не становится картой только из-за формы. Прямые метки ПД имеют приоритет. Источники идей — [PatternRecognizer](https://github.com/data-privacy-stack/presidio/blob/33586b8dc7308cd15427b60764f9e8c1163463c2/presidio-analyzer/presidio_analyzer/pattern_recognizer.py) и [context enhancer](https://github.com/data-privacy-stack/presidio/blob/33586b8dc7308cd15427b60764f9e8c1163463c2/presidio-analyzer/presidio_analyzer/context_aware_enhancers/lemma_context_aware_enhancer.py). Собственные 23 regression-примера улучшились с 9 до 23; это не независимый benchmark. [Тесты](../tests/test_presidio_lessons.py).

Hybrid реализован в [`ner_service.py`](../scripts/ner_service.py), [`ner.py`](../seif/ner.py) и [`app.py`](../seif/app.py). Модель загружается локально до readiness, возвращает только тип, диапазоны PERSON/LOCATION и score. LOCATION сохраняется отдельным типом: модель не выдаёт географическое имя за проверенный полный адрес или город. API передаёт текст по закрытой сети с общим ключом, проверяет ответы и Unicode-смещения, ограничивает размер фрагмента, параллелизм и общий deadline. При отказе NER запрос завершается ошибкой без выдачи исходного текста как успешно защищённого.

API работает на Python 3.14 без GIL; модель изолирована в Python 3.13. Отключены parser/morphologizer/lemmatizer, оставлены `tok2vec + ner`. В отдельной исторической проверке PERSON-only на 76 авторских примерах типы/границы/score совпали полностью; среднее время вызова снизилось **4,064 → 2,752 мс**, p95 **6,123 → 3,738 мс**. Это ограниченная проверка эквивалентности и detector latency, не гарантия для всех текстов и не HTTP SLA. [Измерение оптимизации](ner-pipeline-optimization.json).

## Включение и выбор профиля

Обычный запуск сохраняет профиль правил. Для гибрида используются [`Dockerfile.ner`](../Dockerfile.ner) и [`compose.ner.yaml`](../compose.ner.yaml); NER-порт не публикуется на хост. После подготовки основного `.env` создайте отдельный ключ без вывода и перезаписи существующего файла:

```bash
python3 - <<'PY'
import os
import secrets
fd = os.open('.env.ner', os.O_WRONLY | os.O_CREAT | os.O_EXCL, 0o600)
with os.fdopen(fd, 'w', encoding='ascii') as stream:
    stream.write('SEIF_NER_TOKEN=' + secrets.token_urlsafe(48) + '\n')
PY
docker compose --env-file .env --env-file .env.ner \
  -f compose.yaml -f compose.ner.yaml up --build -d
```

Для Kubernetes подготовлен [hybrid overlay](../deploy/k8s/overlays/hybrid/kustomization.yaml) с двумя NER-репликами и Secret `ner-key`; [инструкция добавления ключа](kubernetes.md#необязательный-hybrid-профиль-с-presidio-ner) сохраняет существующие секреты. Манифесты проверены статически; факт запуска кластера этим не подтверждается.

Рекомендация по измерениям: правила дают высокую precision, но существенно пропускают сущности на сложных корпусах; финальный hybrid расширяет поиск имён и географических сущностей ценой модели и дополнительных срабатываний. Универсальное превосходство над Presidio не доказано. Для нового языка нужны отдельные recognizers, модель и тест; неизвестный язык строки нельзя подменять предположением о гражданстве. **Результат 2100 RPS базового режима не является SLA гибрида**; нагрузочные результаты выбранного развёртывания публикуются отдельно в [validation.md](validation.md).

Presidio имеет [MIT-лицензию](https://github.com/data-privacy-stack/presidio/blob/main/LICENSE); исходники recognizers в СЕЙФ не копировались. Presidio подключён пакетом в отдельном NER-образе, версии зависимостей закреплены в [lock-файле](../deploy/ner/requirements-ner.txt). При переносе исходников нужно сохранять copyright/license notices и указать файлы, upstream commit и изменения. Лицензия Presidio не заменяет лицензию подключаемой модели или набора данных; условия внешних корпусов отдельно зафиксированы в [datasets.md](datasets.md).
