# Схемы архитектуры SEIF

Четыре самостоятельные SVG-схемы 1600 × 900 для презентации, web и PDF. Цвета взяты из `web/styles.css`; текст остаётся текстом, все элементы векторные. Внешних шрифтов, изображений, скриптов, `foreignObject` и фильтров нет. Нижние 50 px оставлены свободными для колонтитула презентации. Дата среза: 23 сентября 2026 года, ветка `experiment/rubert-tensorrt`, код `15eea67`.

## Источники и важные границы

- `seif/app.py`: авторизация, ограничения, проверка записи в vault до детекции; правила и NER исполняются последовательно. Повтор исходного запроса с тем же идентификатором может вернуть сохранённый результат без новой детекции. При включённом NER его ошибка не приводит к успешному частичному ответу.
- `seif/detector.py`, `seif/context_filters.py`, `seif/ner_boundaries.py`: контекст, приоритеты, обработка границ. Граф на схеме 04 показывает зависимости данных, не параллельное исполнение.
- `seif/rubert_ner.py`, `seif/rubert_decoder.py`, `seif/ner_contract.py`: GPU RuBERT как опциональный экспериментальный backend, 21 нативный тип → 14 транспортных типов с исходными границами. CPU spaCy ограничен своим объявленным набором типов; схема 04 описывает именно RuBERT.
- `seif/transform.py`, `seif/vault.py`: случайные токены, сопоставления, AES-GCM, HMAC-ключ от tenant и payload ID, TTL. Redis и in-memory vault хранят ciphertext. RAM — локальна процессу и теряется после рестарта. Запись содержит защищённый текст и замены; отдельная полная копия исходного текста не записывается.
- `compose.yaml`, `compose.ner.yaml`, `Dockerfile.ner`: основной профиль — API + Redis; CPU NER подключается отдельно. У Redis в Compose отключено сохранение на диск. NER получает исходный текст по приватному HTTP. Внешний TLS/туннель не является встроенной функцией API.
- `deploy/k8s/base/app.yaml`: начальные 3 реплики API, HPA 2–8. `deploy/k8s/base/redis.yaml`: три pod с Redis и Sentinel. `deploy/k8s/overlays/hybrid/ner.yaml`: две CPU NER-реплики. Ingress — настраиваемый пример, не часть готового домена. GPU-контейнера и GPU-манифестов в этом комплекте нет. Подготовленные файлы не доказывают наличие работающего кластера; асинхронная репликация Redis не гарантирует нулевую потерю последних записей.

Внешнюю LLM интегрирует приложение-потребитель: сервис не вызывает её самостоятельно. Схемы не обещают стопроцентную детекцию или отсутствие утечек. Восстановление разрешает политика tenant; изменённые, неизвестные или просроченные токены могут не восстановиться. Опциональная запись исходных запросов для измерений находится вне vault и не наследует его шифрование и TTL; на основных схемах этот исследовательский канал не показан.

## Проверка

Каждый SVG отрендерен при размере 1600 × 900 через Sharp / librsvg и визуально проверен: границы блоков, читаемость текста, подписи и ортогональная маршрутизация стрелок. SVG используют обычные `text`, `rect`, `path`, `circle` и маркеры стрелок, чтобы облегчить перенос в редактируемые слайды.
