# СЕЙФ — архитектура и эксперименты

16 слайдов и четыре самостоятельные векторные схемы в стиле существующего web-интерфейса: тёмный зелёный фон, мятные акценты, Segoe UI и Georgia. Срез кода — `15eea67`, ветка `experiment/rubert-tensorrt`, 23 сентября 2026 года.

## Главные выводы

Архитектура хорошо разделяет API, правила, NER, политику и зашифрованное хранилище восстановления. Для следующего этапа нужны измеряемое управление очередью NER, проверка восстановления после сбоев Redis, эксплуатация ключей и отдельный срок хранения raw capture. Kubernetes-манифесты подготовлены; работа реального кластера этой проверкой не подтверждалась. Внешнюю LLM вызывает приложение-потребитель.

Текущий RuBERT-профиль дал **97,13 / 77,86 / 93,90% F1 маскирования** на Organizer / PII-Bench / RedMadRobot. На RMR точный тип и границы дают **86,76% common14 F1**, тогда как контроль pii-guard — **89,85%**. Превосходства по всем метрикам нет. Контроль pii-guard использует исходный текст без полного upstream-препроцессинга; это не воспроизведение опубликованного model-card score.

Последний сохранённый HTTP-замер RuBERT: **533,74 успешных mask RPS**, **p95 19,58 мс**, **0 ошибок из 22 300**, concurrency 8. Один API-worker, один NER-worker, loopback и in-memory vault. Это измеренный режим, не максимальная ёмкость и не SLA. GLiNER 31,89 / 49,86 RPS измерялся ранее с другим протоколом C4/446; сравнение напрямую не изолирует влияние модели.

После вопроса о GLiNER выполнены строгая проверка предобработки **5 095 документов / 5 179 окон** и CPU replay сохранённых предсказаний. RuBERT-подобный сдвиг слов не обнаружен. С текущими правилами GLiNER дал **97,46 / 74,29 / 70,47%**, ранее — **97,46 / 71,76 / 65,66%**. GPU inference и нагрузка заново не запускались. В старой схеме GLiNER запрашивались PERSON/LOCATION, а не весь набор PII: для полной схемы нужен отдельный новый модельный эксперимент.

Organizer — предварительная AI silver-разметка, не официальный gold организаторов. Все три корпуса уже использовались в разработке; это регрессионная оценка, не независимый holdout. Исходные запросы в презентационный комплект не входят.

## Источники и проверка

- [architecture-evidence.json](architecture-evidence.json): факты, файлы и SHA-256 исходников.
- [experiment-metrics.json](experiment-metrics.json): значения, JSON pointers, условия и SHA-256 источников; исторические значения сохранены отдельно.
- [gliner-recheck-metrics.json](gliner-recheck-metrics.json): агрегаты новой CPU-проверки без исходных текстов.
- [seif-architecture.pptx-qa.json](seif-architecture.pptx-qa.json): 16 слайдов, 16 страниц заметок, редактируемый текст, 0 растровых вставок; границы и совпадение текста проверены.

Web-версия отрендерена Chromium; проверены все 16 слайдов, границы текста, переключение слайдов, обзор и заметки. PDF имеет 16 страниц, кириллический текст и векторную графику. PPTX проверен структурно и по тексту, без запуска Microsoft PowerPoint. Разные офисные приложения могут немного изменить базовые линии шрифтов и штрихи; PDF служит фиксированным вариантом для отправки.

## Пересобрать

Генераторы не запускают сервис и не меняют модели. Нужны Python 3.10+ (stdlib), Node.js 20+, `pptxgenjs` 4.0.1, `playwright` 1.62.1, Chromium и локальные шрифты Segoe UI / Georgia / Consolas. Шрифты не распространяются в комплекте. Конвертер PPTX ищет TTF в `/mnt/c/Windows/Fonts` либо `C:/Windows/Fonts`; текущая сборка выполнена в WSL.

Из корня репозитория:

```bash
python3 docs/presentation/build_presentation.py
python3 -m http.server 8791 --bind 127.0.0.1 --directory docs/presentation
```

Во втором терминале:

```bash
node docs/presentation/export_web.cjs
node docs/presentation/export_pptx.cjs
```

По умолчанию экспорт использует установленный на рабочей машине runtime. На другой машине задайте `SEIF_DOCUMENT_NODE_MODULES` (каталог с `playwright`), `SEIF_CHROMIUM` (путь к исполняемому Chromium), `PPTXGENJS_MODULE` (путь к модулю `pptxgenjs`, либо установите его обычным способом). В WSL нужно подключить Windows-шрифты к Fontconfig, например через пользовательский `fonts.conf` и `FONTCONFIG_FILE`. Чтобы построить только HTML/SVG, Node.js и офисное ПО не нужны.

Исходники: `build_presentation.py` и `template.html`; промежуточные SVG — `slides/`; editable scene — `seif-architecture.scene.json`. `export_web.cjs` пишет проверочные скриншоты и отчёт в игнорируемый каталог `output/playwright/seif-presentation/`.
