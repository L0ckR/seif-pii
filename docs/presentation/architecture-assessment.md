## Поток нового запроса

1. Клиент передаёт `payload`, `payload_id`, `X-System-ID` и `X-API-Key`. Исключение — явно включённый anonymous demo.
2. ASGI middleware ограничивает количество запросов, размеры тела, суммарные байты буфера и время загрузки. FastAPI проверяет JSON. Затем обработчик авторизует tenant и применяет rate limit.
3. HMAC формирует ключ из tenant + payload ID и отпечаток текста. API читает vault. Повтор исходного текста с тем же ID возвращает ранее сохранённый результат; это идемпотентность, а не новый inference.
4. Правила находят контакты, документы, имена, адреса и структурированные поля. При включённом NER **после правил** вызывается модель по private HTTP. Модель получает исходный текст, а возвращает только интервалы, тип и score. Длинные запросы разбиваются на перекрывающиеся окна с исходными Unicode-смещениями.
5. Merge проверяет модельный контракт, разрешает пересечения и применяет контекст. Политика выбирает типы, режим и условия совместной встречаемости.
6. Преобразование создаёт маску, токены или демонстрационные значения. Результат и необходимые исходные фрагменты запечатываются AES-GCM и записываются в vault с TTL. Только после успешной записи API возвращает результат.

Критическая подробность для схемы: **rules → NER выполняются последовательно**; между разными HTTP-запросами есть асинхронное выполнение. При ретрае распознавание может вообще не запускаться. [seif/app.py:384](../../seif/app.py#L384), [seif/app.py:414](../../seif/app.py#L414), [seif/app.py:448](../../seif/app.py#L448), [seif/ner.py:154](../../seif/ner.py#L154).

## Восстановление и хранение

| Режим | Результат | Что можно восстановить |
|---|---|---|
| `mask` | Буквы и цифры заменяются `*`, пунктуация и структура остаются | Точный сохранённый результат |
| `token` | Случайные типизированные токены; одинаковые значения одного типа внутри запроса получают один токен | Точный результат; `/v1/unmask` также восстанавливает известные токены после перестановки/повтора в изменённом ответе |
| `synthetic` | Демонстрационные значения; для неподдержанного типа — символьная маска | Точный сохранённый результат |

`/process` поддерживает протокол хакатона: исходный текст → результат → исходный текст при том же ID. Для изменённого ответа LLM с известными токенами нужен `/v1/unmask`. Нужны тот же tenant/ID, право `allow_unmask` и живое соответствие. Чужой текст с занятым ID даёт 409; отсутствующее соответствие — 410. Это не восстановление произвольно отредактированной звёздочной маски. [seif/app.py:320](../../seif/app.py#L320), [seif/app.py:414](../../seif/app.py#L414), [seif/transform.py:35](../../seif/transform.py#L35).

TTL по умолчанию — 900 секунд. AES-256-GCM применяется **до записи и в RAM, и в Redis**; HMAC-ключ tenant/ID служит associated data. Сохраняется маскированный текст и исходные заменённые фрагменты, если восстановление разрешено. `SET NX` атомарно выбирает одну запись для конкурентных запросов. [seif/config.py:104](../../seif/config.py#L104), [seif/vault.py:74](../../seif/vault.py#L74), [seif/vault.py:107](../../seif/vault.py#L107), [seif/app.py:400](../../seif/app.py#L400).

RAM изолирована внутри процесса и теряется при рестарте. Прилагаемый supervisor запрещает несколько API-workers без общего Redis/Sentinel. Compose использует один Redis без AOF/RDB и без реплик. Kubernetes предусматривает AOF `everysec`, PVC, три Redis/Sentinel и ограничение записи при недостатке свежих реплик, но асинхронная репликация допускает потерю уже подтверждённых соответствий. **Zero-RPO из этой архитектуры не следует.** [scripts/serve.py:16](../../scripts/serve.py#L16), [compose.yaml:26](../../compose.yaml#L26), [docs/kubernetes.md:177](../kubernetes.md#L177).

## Границы доверия

- **Клиент → API:** исходный текст и API-ключ; TLS обеспечивает внешний ingress/tunnel. API не может предотвратить обход шлюза самим интегратором.
- **API → NER:** исходный текст внутри доверенного контура, отдельный Bearer, bounded contract. Наличие private HTTP и NetworkPolicy не равно mTLS. NER не требуется master key vault или клиентский API-ключ.
- **API → vault:** ciphertext и HMAC-ключи; шифрование записей не заменяет безопасность транспорта, процессов и ключей. Внутренний Redis/Sentinel в подготовленном комплекте работает с паролем без TLS.
- **Обычный аудит:** metadata, типы, request ID и длительности без исходного текста. Метрики имеют фиксированную кардинальность; `/metrics` авторизуется.
- **Опциональный capture:** отдельная bounded writer queue → локальный plaintext JSONL. Это исключение из обычного аудита: исходный текст действительно сохраняется, не шифруется vault и не удаляется его TTL. Права 0700/0600 и `.gitignore` полезны, но не являются retention-политикой. IP-метаданные не доказывают личность организатора.

## Сильные стороны

**Модельный слой отделён от API.** Тяжёлые библиотеки работают в отдельном окружении, а интерфейс допускает замену spaCy на RuBERT без изменения публичного контракта. Это практическое преимущество для Python без GIL и несовместимых GPU-зависимостей.

**Обратимость спроектирована вместе с API.** Tenant isolation, idempotency, конфликты ID и TTL имеют явные результаты. Ошибка хранилища или NER не превращается в успешный обход защиты. При этом fail-closed описывает отказ компонента, а не обещает отсутствие пропусков распознавания. [seif/app.py:487](../../seif/app.py#L487).

**Есть ограничение ресурсов и диагностические этапы.** HTTP/body/CPU/NER capacity ограничены, длительные работы корректно освобождают ёмкость после фактического завершения, Prometheus и stage timings позволяют искать узкое место. Capture работает best effort и может отбрасывать записи; без измерения нельзя обещать нулевое влияние на RPS.

## Как показывать архитектуру на слайдах

Использовать сплошные линии для реализованного runtime, пунктир — для опционального подключения и подготовленного deployment. На схеме запроса выделить ранний путь idempotent retry и отдельный restore. На схеме профилей подписать реальную модель, среду и размер таксономии; GPU не показывать частью текущего default Compose. На схеме данных обозначить plaintext до/внутри NER, ciphertext vault и отдельный capture. Kubernetes-слайд назвать «Подготовленная схема развёртывания» и явно отметить отсутствие принятого GPU overlay.

Цифры экспериментов брать из исходных JSON/отчётов с указанием корпуса, протокола и профиля. Текущий RuBERT выиграл по F1 маскирования у прежнего RuBERT, но не превосходит pii-guard по всем метрикам. Сравнение pii-guard — raw-text ablation, не полный pipeline; organizer имеет предварительную AI-разметку. Эти ограничения меняют смысл вывода, поэтому должны быть видимы непосредственно на слайде с качеством. [QUALITY_NOTES.md:120](../../benchmarks/ner-models/rubert-upgrade/QUALITY_NOTES.md#L120).
