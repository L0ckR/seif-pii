# Локальная запись разрешённого прогона

Для разрешённого сохранения исходных запросов задайте `SEIF_REQUEST_CAPTURE_DIR`
внутри `local-data/hackathon-requests/` и перезапустите API. Без этой переменной
запись отключена. `local-data/` исключён из Git, контекста Docker и ZIP исходников.

Каждый worker пишет свой `requests-<pid>-<uuid>.jsonl` с правами 0600 в каталог
0700. Сохраняются POST `/process`, `/v1/mask`, `/v1/unmask`: исходный JSON запроса,
`payload`, `payload_id`, время получения и завершения в UTC, код ответа, длительность,
идентификатор запроса и успешная операция `mask`/`unmask`. Сохраняются также вызовы
с ошибкой; для отклонённого до чтения тела запроса `body_complete` будет false.
У некорректного JSON сохраняются метаданные и `parse_error`, без исходного тела.

Для определения происхождения сохраняются `client_ip`, `cf_connecting_ip`,
`forwarded_for`, `cf_ray`, `user_agent`. `client_ip` может уже отражать обработку
доверенного прокси в Uvicorn. Поле `source_ip` предпочитает корректный адрес из
`CF-Connecting-IP`. Это свидетельства сетевого происхождения, а не удостоверение
личности организатора: исходный API должен оставаться доступен только через
доверенный туннель. Ключи API, Authorization, Cookie и произвольные заголовки
не копируются. Наши проверки помечаются `X-SEIF-Capture-Probe` и уникальными
`payload_id`; список известных проверок сохраняется в локальном манифесте сессии.

Запись выполняется отдельным потоком через ограниченную очередь. По умолчанию
для каждого worker разрешены 64 MiB очереди, 8192 элемента и 2 GiB JSONL. Настройки:
`SEIF_REQUEST_CAPTURE_MAX_QUEUED_BYTES`, `SEIF_REQUEST_CAPTURE_MAX_RECORDS`,
`SEIF_REQUEST_CAPTURE_MAX_DISK_BYTES`. Превышение лимита не останавливает API,
но увеличивает `dropped`. Ошибки записи учитываются в `write_errors`.

Файл `worker-<pid>.json` обновляется примерно раз в секунду и содержит только
счётчики: `submitted`, `written`, `dropped`, `write_errors`, `bytes`,
`queued_records`, `queued_bytes`. Перед выводом о полноте захвата убедитесь,
что очередь опустела, `dropped` и `write_errors` равны нулю, а число полных строк
JSONL соответствует `written`. При штатном завершении очередь дописывается и
вызывается fsync; аварийное завершение может потерять ещё не записанный буфер.

Результирующие файлы сохраняют повторные HTTP-вызовы и порядок каждого worker.
Общий порядок можно восстановить сортировкой по `received_at`. Для повторной
нагрузки создавайте новые `payload_id`. При подготовке набора оригиналов отбирайте
успешные операции `mask` и исключайте известные проверки по манифесту, IP и времени;
входящие операции `unmask` содержат уже маскированный текст. Эти записи не содержат
эталонную разметку организаторов и сами по себе не позволяют измерить F1.
