# СЕЙФ

**Данные работают. Личное остаётся личным.**

Рабочий модуль защиты персональных данных для цепочки «потребитель → LLM → потребитель», подготовленный по `ds.pdf`. Включает API для автоматической проверки, интерактивную русскоязычную панель, 24 типа сущностей, три обратимых способа замены, политики систем, зашифрованное TTL-хранилище и воспроизводимые проверки.

Основной стек: **CPython 3.14.7 без GIL + FastAPI/Uvicorn + Redis + AES-256-GCM**. Детектор полностью локальный; внешняя LLM, платный API, GPU, загрузка моделей и интернет во время обработки не нужны. Обоснование выбора вместо преждевременного переноса на Go, проверки совместимости и измерения: [выбор стека](docs/stack.md).

## Что можно показать на защите

1. Открыть интерфейс, защитить карточку клиента, увидеть выделенные сущности и объяснения, затем восстановить текст посимвольно.
2. Переключить `token`, `mask`, `synthetic` и сравнить то, что увидит модель.
3. Выбрать «Контекст важен»: поэт Пушкин, публичный адрес и ИНН банка остаются открытыми; аналогичная запись о клиенте защищается.
4. Показать иностранный документ, карточные реквизиты и сочетание CARD + PIN в политике `card-support`.
5. Выполнить парный `/process`, повторить оба запроса и убедиться, что ретраи не переключают операцию.

Демонстрационный стенд предназначен для вымышленных данных. Публичный Cloudflare Tunnel заканчивается вне банковского контура; реальные данные банка должны обрабатываться в его собственной инфраструктуре. Quick Tunnel работает, пока запущены компьютер, сервис и туннель; это не постоянный облачный хостинг.

## Быстрый запуск

Нужен актуальный [uv](https://docs.astral.sh/uv/) с каталогом Python 3.14.7 (проверен uv 0.12.17).

```bash
uv python install 3.14.7t
uv venv --python 3.14.7t
uv pip install -r requirements.lock
uv pip install -e '.[dev]'
make run
```

Откройте `http://127.0.0.1:8765`. В локальном demo заголовки не требуются; `/health` показывает сборку Python, фактическое состояние GIL и используемое хранилище. Не запускайте несколько workers с RAM-хранилищем: для нескольких процессов обязателен Redis и общий `SEIF_MASTER_KEY`.

```bash
# В другом терминале; cloudflared должен быть установлен
bash scripts/tunnel.sh
```

## Развёртывание с Redis

```bash
cp .env.example .env
# Сгенерировать значение SEIF_MASTER_KEY (32 случайных байта в base64)
python3 -c 'import secrets,base64; print(base64.b64encode(secrets.token_bytes(32)).decode())'
# В .env задать ключ и случайный SEIF_DEMO_API_KEY; SEIF_DEMO=0
docker compose up --build -d
```

Docker собирает отдельный интерпретатор 3.14.7t, проверяет отключение GIL на старте и запускает приложение от непривилегированного пользователя. Redis не публикуется на хост, хранит только зашифрованные объекты, использует TTL и `noeviction`. Внешний доступ организуйте через TLS reverse proxy или именованный туннель. Для проверки организатором без заголовков временно включается изолированный `SEIF_DEMO=1` и убирается `SEIF_DEMO_API_KEY`; после прогона возвращаются ограничения доступа.

На этой машине Docker-движок отсутствовал: проверены нативные запуски и реальный Redis, а сборка образа вынесена в CI. Детали эксплуатации и ограничения — [безопасность](docs/security.md), [архитектура](docs/architecture.md).

## Контракт проверки

```http
POST /process
Content-Type: application/json

{"payload":"Клиент Иванов Иван Иванович, паспорт 4509 123456","payload_id":"example-001"}
```

```json
{"result":"Клиент ****** **** ********, паспорт **** ******"}
```

Второй запрос содержит полученную маску и тот же `payload_id`: возвращается исходный текст. Повтор исходного текста возвращает ту же маску, повтор маски — тот же исходный текст; конфликт ID с другим содержимым даёт `409`. Если ПД не найдены, оригинал и маска совпадают, и оба шага возвращают этот текст. Соответствие действует в пределах TTL; истечение TTL не позволяет восстановить данные.

Полная спецификация контракта: [process_api.yaml](process_api.yaml); OpenAPI действующего сервиса: `/openapi.json`.

| Метод | Назначение |
|---|---|
| `POST /process` | Точный контракт организатора: `{payload,payload_id}` → `{result}` |
| `POST /v1/mask` | Защита; дополнительно принимает `mode`, возвращает типы, объяснения, диапазоны и время |
| `POST /v1/unmask` | Восстановление; в режиме `token` поддерживает перестановку/повтор известных токенов в ответе LLM |
| `GET /v1/types` | Словарь поддержанных типов |
| `GET /health` | Readiness, режим, хранилище, Python и GIL |
| `GET /metrics` | Prometheus; в restricted режиме требуется ключ допущенной системы |

Маска сохраняет позиции пробелов и знаков, скрывая все буквы/цифры распознанных участков. Синтетика использует явно макетные значения, например `person1@example.invalid`, а не потенциально действительные банковские реквизиты. Для свободно изменяемого моделью ответа используйте `token`; обычная маска и синтетика требуют точного защищённого текста. Готовая цепочка с локальной имитацией LLM: `python scripts/client_example.py`.

## Настройка за пять предложений

1. В `config/policies.yaml` добавьте систему с `enabled` и именем переменной окружения ключа в `api_key_env`.
2. В окружении задайте этот ключ, `SEIF_MASTER_KEY` и, для общего хранилища экземпляров, `SEIF_REDIS_URL`.
3. Выберите `types`, `mode`, `allowed_modes`, `allow_unmask`, `min_types` и `required_types`.
4. При необходимости добавьте `extra_rules` с `type` и `pattern`, настройте `rps` и перезапустите сервис.
5. Передавайте `X-System-ID` и `X-API-Key`, создавайте новый `payload_id` для каждого текста и сохраняйте его для восстановления и ретраев.

Регулярные выражения расширений ограничены длиной, количеством и временем исполнения; неизвестный тип или неверное правило останавливают старт. В `card-support` приведён бонусный сценарий: защищать только при наличии карты и второго типа. Это осознанное исключение политики; по умолчанию любой распознанный тип защищается независимо.

## Проверки и измерения

```bash
make lint
make test
make evaluate
# Отдельная тестовая Redis DB; тесты удаляют только свои UUID-ключи
SEIF_TEST_REDIS_URL=redis://127.0.0.1:6385/15 .venv/bin/python -m pytest tests/test_redis.py -q
python scripts/benchmark.py --url http://127.0.0.1:8765 --rps 2000 --duration 300 --output output/load.json
uv pip install tiktoken==0.14.0
python scripts/large_input.py
make zip
```

Фактические результаты и условия измерений собраны в [отчёте проверок](docs/validation.md), исходные числа — в JSON рядом с ним. Тесты охватывают все заявленные категории, ложные срабатывания, точное восстановление, ретраи, конкурентную запись, изоляцию систем, повреждение шифротекста, TTL, запрет демаскирования, ошибки конфигурации, отсутствие ПД в логах и лимиты.

**Граница результатов:** набор `scripts/evaluate.py` содержит 48 синтетических примеров разработки; он не является независимым банковским корпусом и не подтверждает 95% на закрытом эталоне. Он считает exact-span F1, а организатор — нормированное span-based расстояние Левенштейна; точная эталонная маска в PDF не раскрыта. Локальная нагрузка не доказывает скорость через публичный туннель или на другом железе. TPS в `/metrics` оценивается как characters/4 и явно помечен `estimated`; точный TPS зависит от токенизатора модели.

## Комплект сдачи

`make zip` создаёт **`output/seif-pii-source.zip`**: только исходники, конфигурация и текстовые документы реализации, без ключей, зависимостей, исходного PDF, датасетов, скриншотов, бинарников и каталогов сборки. CI проверяет код на обычной и free-threaded сборках, запускает тесты с Redis и сохраняет ZIP. Требования по каждому пункту и бонусы сопоставлены с реализацией в [матрице приёмки](docs/requirements.md).

Для официальной сдачи нужно загрузить ZIP в систему организатора и указать действующий URL `/process`; внешние AlfaSonar/нагрузочные проверки не подменяются этим локальным отчётом. Заявление о соответствии нормативной базе РФ и стандартам конкретного банка требует их отдельной приёмки: данный репозиторий такой аттестацией не является.

## Kubernetes и репликация

[Инструкция Kubernetes](docs/kubernetes.md) описывает Kustomize-развёртывание: три реплики API, HPA, PDB, readiness/liveness, NetworkPolicy, три Redis/Sentinel, PVC и AOF. Sentinel-клиент приложения переживает смену primary; это проверено выключением ведущего Redis с последующим точным восстановлением текста тем же экземпляром API ([результат](docs/sentinel-failover.json)). Асинхронная репликация может терять последние неподтверждённые репликами записи; zero-loss не заявляется.

```bash
kubectl kustomize deploy/k8s
# После подключения к целевому кластеру следуйте bootstrap-процедуре в docs/kubernetes.md
```

Секреты создаются отдельным скриптом и в Git не сохраняются. Production overlay требует разнести Redis по узлам; базовая конфигурация позволяет локальный стенд. CI собирает образ, проверяет запуск и публикует его в GHCR, связанный с приватным репозиторием; приватному кластеру нужен доступ к registry. Наличие валидных манифестов само по себе не означает, что Kubernetes-кластер уже развёрнут.
