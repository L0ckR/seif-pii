# СЕЙФ

**Данные работают. Личное остаётся личным.**

Модуль защиты персональных данных для цепочки «потребитель → LLM → потребитель» по `ds.pdf`: API проверки, русскоязычная панель, 24 исходных типа и дополнительный `LOCATION`, три обратимых режима, политики систем и зашифрованное TTL-хранилище.

Основной профиль — **Python 3.14.7 без GIL + FastAPI/Uvicorn + Redis + AES-256-GCM**. Необязательный `hybrid` добавляет локальный Presidio PERSON/LOCATION NER-сервис на Python 3.13. Внешняя LLM, платный API и GPU не нужны; модель устанавливается при сборке NER-образа, интернет при обработке не используется. [Выбор стека](docs/stack.md), [сравнение с Presidio](docs/presidio.md).

## Что реализовано

- `mask`, `token`, `synthetic` с точным восстановлением; известные токены допускают перестановку и повторение в ответе LLM.
- Российские банковские типы, контекстные исключения публичных упоминаний, адресная грамматика «улица + дом» и компоненты адреса. [Границы адресного разбора](docs/address-extraction.md).
- Ограниченные форматы идентификаторов Казахстана, Украины, Узбекистана, Кыргызстана, Беларуси, Молдовы и Азербайджана; это не полное покрытие языков и документов этих стран. [Форматы и первоисточники](docs/cis.md).
- Ключи и политики систем, изоляция `payload_id`, TTL, лимиты, аудит без исходного текста, Prometheus, Redis Sentinel и подготовленные Kubernetes-манифесты.

На защите можно замаскировать карточку клиента, показать диапазоны и причины, сравнить три режима и восстановить текст. Пример «Контекст важен» показывает публичного поэта и адрес банка; политика `card-support` демонстрирует защиту только при сочетании типов. Демонстрационный стенд и примеры используют вымышленные данные.

## Быстрый запуск

Нужен [uv](https://docs.astral.sh/uv/) с поддержкой Python 3.14.7; проверена версия uv 0.12.17.

```bash
uv python install 3.14.7t
uv venv --python 3.14.7t
uv pip install -r requirements.lock
uv pip install -e '.[dev]'
make run
```

Интерфейс: `http://127.0.0.1:8765`. Локальный demo не требует заголовков. `/health` показывает профиль детектора, хранилище и фактическое состояние GIL. Несколько workers требуют общего Redis и одинакового `SEIF_MASTER_KEY`; RAM-хранилище используется одним процессом.

Для временного публичного URL при установленном `cloudflared`:

```bash
bash scripts/tunnel.sh
```

Основной демонстрационный URL обслуживает профиль правил. Quick Tunnel работает, пока запущены компьютер, сервис и туннель; постоянный облачный хостинг этим не создаётся. Реальные банковские данные должны оставаться в согласованном защищённом контуре.

## Redis и необязательный NER

Создайте защищённый `.env` с двумя случайными ключами; существующий файл не перезаписывается, ключи не выводятся:

```bash
python3 - <<'PY'
import base64
import os
import secrets
fd = os.open('.env', os.O_WRONLY | os.O_CREAT | os.O_EXCL, 0o600)
with os.fdopen(fd, 'w', encoding='ascii') as stream:
    stream.write('SEIF_MASTER_KEY=' + base64.b64encode(secrets.token_bytes(32)).decode() + '\n')
    stream.write('SEIF_DEMO_API_KEY=' + secrets.token_urlsafe(48) + '\n')
    stream.write('SEIF_DEMO=0\nSEIF_TTL_SECONDS=900\n')
PY
docker compose up --build -d
```

Docker запускает API непривилегированно с read-only rootfs. Базовый Compose использует один Redis без дисковой персистентности; Redis не публикуется на хост, хранит ciphertext и применяет `noeviction`. Сохранность при перезапуске Redis и репликацию предоставляет отдельная [конфигурация Kubernetes/Sentinel](docs/kubernetes.md).

Чтобы добавить Presidio, выполните [инструкцию hybrid](docs/presidio.md#включение-и-выбор-профиля): отдельный `.env.ner`, общий `SEIF_NER_TOKEN` и `compose.ner.yaml`. Модель возвращает PERSON/LOCATION-кандидатов, которые проходят правила объединения и политику СЕЙФА. `LOCATION` обозначает общую географическую сущность и не выдаётся за полный личный адрес или `CITY`. При недоступности NER hybrid возвращает ошибку защиты; незаметного перехода к неполному результату нет. Образ API уже опубликован в приватный GHCR; публикация отдельного NER-образа ожидает успешного CI, локальная сборка предусмотрена.

## Контракт проверки

```http
POST /process
Content-Type: application/json

{"payload":"Клиент Иванов Иван Иванович, паспорт 4509 123456","payload_id":"example-001"}
```

```json
{"result":"Клиент ****** **** ********, паспорт **** ******"}
```

Второй запрос содержит маску и тот же `payload_id`: возвращается исходный текст. Ретраи исходного текста возвращают ту же маску; ретраи маски — тот же оригинал. Другой текст с занятым ID даёт `409`; после TTL восстановление недоступно. Если ПД не найдены, оба шага возвращают неизменённый текст. Спецификация: [process_api.yaml](process_api.yaml); OpenAPI: `/openapi.json`.

| Метод | Назначение |
|---|---|
| `POST /process` | Контракт организатора: `{payload,payload_id}` → `{result}` |
| `POST /v1/mask` | Защита с `mode`, типами, причинами, диапазонами и временем |
| `POST /v1/unmask` | Восстановление; token допускает изменённое окружение известных токенов |
| `GET /v1/types` | Словарь типов |
| `GET /health` | Готовность, профиль, хранилище, Python/GIL |
| `GET /metrics` | Prometheus; restricted режим требует ключ системы |

Маска сохраняет разделители, скрывая буквы и цифры распознанных участков. Синтетика использует макетные значения; для восстановления mask/synthetic нужен точный защищённый результат. Для свободно изменяемого ответа модели предназначен `token`. Пример цепочки: `.venv/bin/python scripts/client_example.py`.

## Настройка за пять предложений

1. Добавьте систему в `config/policies.yaml`, задайте `enabled` и имя переменной ключа в `api_key_env`.
2. В окружении задайте этот ключ, `SEIF_MASTER_KEY` и общий `SEIF_REDIS_URL` либо Sentinel-настройки из runbook.
3. Выберите `types`, `mode`, `allowed_modes`, `allow_unmask`, `min_types` и `required_types`.
4. При необходимости добавьте ограниченные `extra_rules`, настройте `rps` и перезапустите сервис.
5. Передавайте `X-System-ID` и `X-API-Key`, создавая новый `payload_id` на текст и сохраняя его для ретраев и восстановления.

## Проверенные результаты

| Проверка | Результат | Граница |
|---|---|---|
| Первый внешний HiveTrace, common4/domain | F1: правила **99,20%**, Presidio RU **96,26%**, hybrid **97,36%** | 612 целых примеров/315 сущностей; замороженная версия до новой адресной грамматики |
| Адреса того же внешнего прогона | Recall адресных символов правил **52,30%** | Существенный пробел; новая грамматика требует следующего holdout |
| Правила + Sentinel, длительный локальный прогон | **2099,98 успешных RPS**, 630 000 запросов за 300 с, p95 **7,339 мс** | До текущих адресных изменений; финальные повторы публикуются отдельно |
| Hybrid, короткий локальный прогон | Предложено 1000 RPS / 30 с; **30 000 ответов 200**, 15 000 точных восстановлений, p95 **221,292 мс** | Фактически **996 RPS** с завершением очереди, без ошибок/пропусков; не длительный SLA и не 2000 RPS |

[Условия, JSON и актуальные проверки](docs/validation.md), [качество и доверительные интервалы](docs/presidio.md), [внешние корпуса](docs/datasets.md). Высокий F1 на четырёх типах не означает 95% покрытия всех требований. Метрика организатора отличается от exact-span F1; результат закрытой проверки не заявляется. Показатели локального стенда не переносятся на туннель, другое железо или тексты по 100 000 токенов. В отдельном большом запросе hybrid маскировал 100 000 токенов за 2,641 с ([отчёт](docs/large-input-hybrid.json)): одновременное обещание NER, такого размера и latency менее секунды не даётся. Таблица hybrid относится к прежнему PERSON-only профилю; расширение LOCATION проверяется отдельно.

## Репликация, Kubernetes и сдача

[Kustomize/runbook](docs/kubernetes.md): три API-реплики, HPA/PDB, probes, NetworkPolicy, три Redis/Sentinel, PVC/AOF и необязательный hybrid overlay. Отключение настоящего primary проверено с последующим восстановлением текста через тот же API. Асинхронная репликация допускает потерю последних записей; zero-loss не заявляется. Манифесты прошли статическую проверку, подключённый Kubernetes-кластер в этой сессии отсутствует.

`make zip` создаёт `output/seif-pii-source.zip`: исходники, тесты, Docker/Compose/Kubernetes, CI и документы; без ключей, зависимостей, PDF, исходных датасетов и бинарников. CI проверяет обычный Python и 3.14t, Redis, контейнеры и ZIP. [Матрица всех пунктов ТЗ](docs/requirements.md).

Для официальной приёмки остаются загрузка ZIP и действующего URL `/process` в систему организатора, внешняя проверка качества и банковское согласование. Локальные тесты не являются результатом AlfaSonar или подтверждением нормативной аттестации.
